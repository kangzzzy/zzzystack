# 승인된 작업 추진

실행 조건: 호스트가 예약/이벤트로 호출. 먼저 `$zzzystack` 또는 `/zzzystack`의 공통 원칙과 프로젝트 정책을 읽는다.

프로젝트 승인·자동화 활성화·수치 한도·실제 계량/중단 기능·프로젝트 잠금을 확인한다. 하나라도 미충족이면 실행 대기로 보고한다. 단순 `enabled: true`를 권한으로 해석하지 않는다.

실행 전 실제 작업 상태를 조회한다. 운영 장애 → 출시 목표 → 정기 작업 → 개선 순서로 의존성 없는 작업을 선택한다. 프로젝트의 활성 작업 한도를 지킨다. 승인 대기 작업의 후속 작업은 선택하지 않는다. 새 개선이 출시 목표를 방해하면 후보로만 남긴다.

필요한 작업 절차를 호출하고 상태·검증·승인·사용량을 기록한다. 주요 변경·판단 충돌·한도 도달은 보류·알림 처리한다. 긴급 문제도 예외 없다. 사용량 부족 시 도구 전환을 해당 작업 범위로 질문한다.

지속적인 무한 루프를 프롬프트 안에서 만들지 않는다. 한 번의 호출은 한 작업의 유효한 단계 또는 명확한 보류 결과로 끝낸다.
