# Automations

전문 역할과 분리된 재사용 실행 지침 묶음이다. [Benny](https://github.com/cursor/plugins/tree/main/pstack/automations/benny)의 소스/프로젝트 설정 분리 방식에서 영감을 받았으며 소스 코드를 복제하지 않았다.

## 제공하는 pack

- `progress`: 승인된 대기 작업을 우선순위·의존성에 맞춰 추진
- `report`: 정기·요청 보고
- `resume`: 중단 후 상태 대조·재개

`npm run setup -- automation report --project PATH`는 호스트에 전달할 프롬프트를 출력한다. 실행·예약·외부 메시지 전송은 하지 않는다. Claude Code/Codex의 실제 호스트 스케줄러는 이 프롬프트를 사용하도록 별도 연결한다.

## 활성화 계약

1. 프로젝트 설정·역할·작업 권한을 사용자가 승인한다.
2. 실행기는 프로젝트 잠금, 의존성 확인, 실행 ID·외부 반영 기록을 영속화해야 한다.
3. 프로젝트/전체 비용과 동시 작업 자원을 원자적으로 예약한다. 측정·중단을 보장할 수 없는 비용 한도 아래에서 무인 실행을 켜지 않는다.
4. 재시도·승인 대기·도구 전환 권한을 재시작 후에도 보존한다. 승인 대기는 자동 해제하지 않는다.
5. 결과 불명 외부 작업은 조회·대조한 뒤 재시도해 중복 실행을 막는다.
6. 정기 보고는 설정 시각에, 승인·충돌·한도·장애는 사건 발생 시 보고한다. 변화 없는 사건 알림은 반복하지 않는다.

현재 버전은 **pack과 프롬프트 렌더러**다. 데몬, 스케줄러, API 비용 계량기, 여러 프로젝트의 자원 배분 실행기는 구현하지 않았다. `enabled`는 설정 의도일 뿐 자동화가 동작한다는 증거가 아니다. 개인 PC 종료 중에는 실행되지 않는다.

자동화 원본은 여기, 프로젝트별 설정·진행 상태는 해당 프로젝트 `.zzzystack/` 또는 명시한 외부 기록에 둔다.
