## 1. 완료로 대조된 결과 불명 명령의 현장 확인 단계가 필수가 아님

**기준:** REQ-06은 ACK timeout이나 이송 중 통신 두절을 결과 불명으로 두고 조회·현장 확인 후 복구하도록 요구한다.

**근거:** architecture.md §4 S3-2는 '결과·위치가 모순되거나 조회 불가이면 현장 확인이 필요'하다고 한정한다. S3-3은 유지보수가 대조 근거를 확정하도록 하고, S3-4의 명시적 현장 확인은 새 명령이 필요한 재계획에 붙는다. 따라서 기존 명령의 완료·위치가 조회에서 일치한 경우 현장 확인 없이 복구 확정할 수 있는 문서 경로가 남는다.

**영향/해결:** 결과 불명 복구의 현장 확인 의무를 조건부 정책으로 완화한다. 요구대로 해당 복구에는 현장 확인을 필수 게이트로 표시하거나, 조건부 생략 정책을 별도 사용자 승인 대상 제안으로 명시해야 한다. 품질 시나리오에 '결과 불명 명령의 조회 결과가 완료여도 현장 확인 전 복구 확정 거부'를 넣으면 검증 가능하다.

이는 실제 구현 우회가 재현된 문제가 아닌 문서상 기준 불일치다. '대조 근거'에 현장 확인을 항상 포함하려는 의도였다면 그 의미를 명시하면 해결된다.

## 합당한 미정 및 일관된 설계

DB/OS/프레임워크, 실제 규격과 주소, 안전 전달 경로, DONE 제한시간, 인증·보존 기간 등을 미정으로 두고 담당 영역과 해결 조건을 남긴 것은 신규 아키텍처 단계에 적절하다. 제어기 부트/순번 계약 미합의 시 대조 완료까지 배정을 차단하고 신선도를 증명하지 못하면 시작/이송을 막는 규칙도 명시한다.

단일 배정 실행자, 원자적 명령·점유 저장 후 송신, 송신 여부 불확실 구간의 재시작 대조, 응답 저장 실패 시 다음 배정·점유 해제 차단, 늦은 DONE의 자동 재개 금지는 문서상 일관된다. 실제 구현이 없다는 이유만으로 해당 설계 제안을 코드 결함으로 취급하지 않는다.

## 재현한 검사와 과장 여부

원본 check.ps1은 읽기 전용 검사로 확인되어 그대로 실행하고 출력을 검토 폴더의 [check-output.txt](check-output.txt)에 보존했다. 원본 산출물/결과는 변경하지 않았다.

관측: 119줄 분량, 고정 입력 해시, 원본 15개 해시, 문서/후보 로컬 링크 존재, Mermaid 단일 닫힌 블록, 추적 ID 16/16 모두 PASS.

Mermaid 검사는 코드 펜스 수와 `mermaid` 문자열 존재만 확인한다. 노드·링크 끝점/문법 파싱이나 실제 렌더링 검사가 아니다. 문서 역시 이 한계를 정확히 밝히므로 Mermaid 또는 행동 검증 과장으로 판단하지 않는다. 원본 로그의 '정적 논리 검토'는 작성자 검토로 구분되어 있다.

시뮬레이터·브라우저·Mermaid 렌더러·역할 인증·저장 중단·실장비/HIL·안전 시간은 실행하지 않았다. 네트워크·설치·재위임 없음. 원본 파일을 수정하지 않고 이 검토 폴더에만 기록했다.
