# 자동화 셀 시험 계획 — Zephyr 자료 적용 초안

입력: [가상 요구사항](requirements.md). D1·D2와 R1을 PC가 조율한다. 실제 장비 사양·프레임워크 채택은 미정이다. 이 문서는 시험 계획이며 아래 시나리오를 실행한 결과가 아니다.

## 원본에서 가져온 부분

Ztest 문서의 suite/case 분리, 단위·통합 계층 및 명시적 assertion을 적용한다. Twister의 PASS/FAIL/BLOCKED/SKIPPED 결과 구분을 참고한다. coverage 문서의 코드 실행 범위 측정은 향후 보조 지표이며 요구사항 통과와 구분한다.

BabbleSim은 주로 무선/SOC 모델용이므로 이 TCP/JSON 셀에 그대로 적용하지 않는다. 다중 장치와 환경을 함께 기동하고 각 실행 결과를 모으는 구조만 참고한다. 원본에는 이 장비의 물리 안전성 또는 자동화 복구 판정기가 없다.

## 환경과 준비 조건

1. 단위: 가상 단조 시계, 명령 큐, 저장소 실패 주입. 결정적 seed와 가상 시간 기록.
2. 통합: PC 제어 서비스와 D1/D2/R1 시뮬레이터. 각 장치가 독립 상태·물리 실행 카운터를 소유한다. PC 상태를 장치 정답으로 재사용하지 않는다.
3. 실장비/HIL: 확정된 통신 규격과 센서/구동기 시험 환경에서 별도 수행. 독립 안전 회로 확인·안전 정지 시간은 승인된 장비 사양과 절차로 평가하며 현재 차단 상태다.

실행 전 대상 버전, 설정, seed, 요구사항 버전, 운영자 역할, 초기 cycle/command/점유·장치 상태를 기록한다. 실제 프로토콜, DONE 시간, 저장 내구성 정책이 필요한 시험은 해당 사양 없으면 BLOCKED다. 각 case 종료 후 fixture를 초기화하고 이전 명령 캐시가 다음 case에 섞이지 않게 한다. 재시작 case만 같은 저장소를 유지한다.

## 시나리오와 판정

## 실행 결과 형식과 종료 조건

결과마다 case ID, 대상 버전, 환경, 자극, 기대/실제 관측, 판정, 로그 경로, 결함 ID를 남긴다. 타이머 허용 오차는 가상 시계에서 0이며 실제 장비 오차/지터는 사양 확정 전 미정이다. 기준을 실행 후 완화하지 않는다.

종료: 필수 case 전부 실행하고 승인된 기대 결과 충족, 열린 중요 결함 해소 후 재시험. BLOCKED/SKIPPED는 통과로 계산하지 않는다. 코드 coverage는 누락 경로를 찾는 보조 자료이며 임의 비율로 장비 안전성을 주장하지 않는다.

## 이번에 실제 수행한 범위

주 에이전트가 고정 원본을 읽고 계획을 작성했다. 다른 후보 결과를 이미 본 상태이므로 독립 비교가 아니다. 실제 시나리오 실행, Zephyr 빌드/Twister, coverage 수집, 브라우저/HIL은 미실행이다. 별도 test-log.md에 문서 검토와 미검증을 기록한다.
