# 가상 셀 HMI 설계 — LVGL 문서 어댑터 탐색 시험

2026-10-14 · 1회 탐색 · 실제 제어 없음

## 입력과 적용 범위

확인된 입력은 이 폴더 requirements.md v1 및 지정 후보 SKILL.md, 연결된 parts_and_states.mdx와 lv_example_event_button.c뿐이다. 다른 후보나 결과는 읽지 않았다. 대상은 D1 가공 → R1 이송 → D2 가공 셀이다. 실제 LVGL 런타임 설치·실행이 아니라 외부 의존성 없는 단일 HTML 시뮬레이션이다. Word/Excel/Figma 양식, 현장 배포 및 안전 검증은 범위 밖이다.

설계 제안: 한 화면에서 장비 카드, 단계/억제 사유, 작업 조작, 가상 제어기 입력, 명령·감사 이력을 위에서 아래로 읽는다. LVGL 채택을 결정하지 않는다. 설계상 실제 상태의 원본은 제어기이며, 샘플에서는 버튼이 가상 제어기 이벤트를 주입한다. 센서·문·안전 신호는 초기 가상 값이며 현장 데이터로 해석하지 않는다.

## 화면과 상호작용

| 영역 | 표시와 동작 | 요구 |
|---|---|---|
| 상단 | 시뮬레이션 표기, 가상 작업자/유지보수 역할 선택 | REQ-09,16 |
| 장비 카드 | D1/D2/R1 상태·연결·최신성·공작물·문·안전 텍스트 | REQ-02,08,10 |
| 사이클 | 단계와 점유 표시, 시작, 일시정지/해제, 억제 사유 | REQ-01,03,09,10 |
| 가상 응답 | ACK, DONE, 다음 단계 배정, 두절, ACK timeout, 재접속 | REQ-04,05,06 |
| 복구 | 상태 대조+현장 확인 후 유지보수만 확정 | REQ-07,09,13 |
| 이력 | command_id/cycle_id/target/type 요청, ACK·DONE, 복구 이벤트 | REQ-04,08,11 |

카드는 색에 의존하지 않고 명시적인 상태 텍스트를 사용한다. 버튼은 키보드 기본 조작과 focus-visible 표시를 갖는다. disabled 및 차단 사유를 함께 표시한다. 제어 모델 act()에서도 시작·이송 조건과 복구 역할을 검사한다. 브라우저 렌더링·스크린리더·터치 영역 실측은 미검증이다.

## 클릭 시나리오

1. 정상: 사이클 시작 → ACK 수신 → DONE 수신 → 다음 단계 배정(R1) → ACK → DONE → 다음 단계 배정(D2) → ACK → DONE. ACK는 수신 확인만 기록하고 단계를 진행시키지 않는다. 점유는 이송 요청 전 확보하고 DONE 후 해제한다.
2. 두절: R1 이송 단계에서 통신 두절 → 결과 불명·OFFLINE·점유 유지. 신규 배정과 완료 주입을 거부한다. 재접속 후에도 상태 미확인·결과 불명을 유지한다.
3. 복구: 재접속 → 상태 대조+현장 확인(가상 D2 적재 완료 스냅샷) → 작업자 복구 거부 → 유지보수 역할 선택 → 복구 확정. D2_READY에서 대기하며 별도 다음 단계 배정이 필요하다. 알람 표시 지우기는 unknown/점유를 해제하지 않는다.
4. 문/안전/일시정지: 해당 가상 입력을 전환하면 신규 시작·이송이 차단된다. 일시정지는 HW 비상정지가 아니며, 진행 중 작업의 저수준 정지를 표현하지 않는다.

## 원본의 구체적 기여

- parts_and_states.mdx의 MAIN/ITEMS 개념을 장비 카드·이력 영역의 분리에 참고했다. LV_STATE_DISABLED는 HTML disabled, FOCUSED/FOCUS_KEY는 focus-visible, PRESSED는 :active로 대응한다. 위젯 상태와 장비 상태를 혼동하지 않도록 장비 상태는 별도 모델에 둔다.
- lv_example_event_button.c의 이벤트 콜백 → 별도 라벨 갱신 구조를 버튼 이벤트 → 모델 처리 → 상태/이력 갱신 구조에 적용했다. 장시간 누르기 반복을 물리 명령에 연결하지 않았다.
- 원본은 통신 계약, 권한, 점유·복구, 저장 원자성 또는 산업 안전을 제공하지 않는다. 이 부분은 입력에 근거한 설계 제안이다. C API를 실행하거나 LVGL 동작과 동등성을 확인하지 않았다.

설계 제안인 운영 서비스 경계에서는 제어기 스냅샷의 유효성, 역할 인증, 원자적 명령 기록을 확인한 다음 요청을 전송해야 한다. 화면의 역할 선택은 인증 수단이 아니며 서버 검사를 대신하지 않는다. 실제 프로토콜/주소/레지스터/제어 주기/안전 정지 시간, HW 상태 확인 절차, 이송 미완료 복구 경로는 미정이다.

## 남은 결함·제약

- 최소 샘플은 한 번의 사이클만 탐색한다. 완료 후 재시작/공작물 재장전 UI가 없다.
- 이송 완료로 확인되는 복구 경로만 구현했다. D1 ACK timeout, 이송 중간 정지 등은 차단 상태로 남으며 복구 UI가 없다.
- 모든 장비 문/안전을 공통 가상 값으로 표시한다. 모터 세부값과 FAULT 주입은 없다.
- 제어기 시뮬레이터와 제어 서비스가 하나의 JS 모델에 있다. 시작/배정 시 PROCESSING/BUSY를 즉시 모사하며 실제 응답 지연을 나타내지 않는다.
- 현재 이력의 명령 ID는 세션 내 유일하고 재로드 후 재사용될 수 있다. 영속성·보안·저장 실패 검증이 없으므로 운영 구현에 사용하면 안 된다.
