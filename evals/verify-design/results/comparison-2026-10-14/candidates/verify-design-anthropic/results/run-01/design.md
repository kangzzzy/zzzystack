# D1 · R1 · D2 셀 HMI 화면 설계

이 산출물은 가상 HMI 시뮬레이션이다. 실제 제어·물리 안전 보장·현장 배포에 사용하지 않는다. Word/Excel/Figma 양식 적합성은 범위 밖이다.

## 입력과 적용 범위

확인된 입력: requirements.md의 REQ-01~16. D1 가공 → R1 이송 → D2 가공 순서, 컨트롤러 상태 원본, 독립 HW 안전 회로, 역할별 복구, 가상 heartbeat 1초·OFFLINE 3초·ACK 대기 2초.
설계 제안: 수동 가상 시계, 한 번에 한 명령, 단일 스냅샷 저장, 결과 불명 복구 시 제어기 조회와 현장 확인 체크 후 유지보수 확정. 실제 통신 대신 버튼으로 제어기 응답을 주입한다. 역할 선택은 데모 기능이며 인증이 아니다.
미정: 실제 주소/레지스터/프로토콜, 제어 주기, DONE 제한시간, 안전 정지 시간, 보존 기간, 실제 인증, 내구성 저장·트랜잭션 구현. 온도 24 °C는 합성 표시 데이터이며 제어 판단에 사용하지 않는다.

## 원본 스킬 적용과 독립성

지정된 verify-design-anthropic 래퍼 및 연결된 frontend-design/SKILL.original.txt만 후보 자료로 읽었다. 다른 후보/평가 결과를 제공받거나 읽지 않은 독립 원본 평가다. 전역 응답 스타일 i-have-adhd는 별도 적용했다.
원본은 시각 방향·타입·토큰·레이아웃·접근성·작성 후 비평에 도움을 준다. 명령 수명주기, 안전, 복구, 저장 원자성 지침은 제공하지 않으므로 아래 설계는 입력 요구사항을 바탕으로 한 제안이며 원본이 보장하는 기능이 아니다.

## 1차 시각 계획 → 검토 → 확정

토큰: 바탕 #edf3f6, 패널 #ffffff, 본문 #183244, 주행 강조 #156587, 경고 #8c4d00, 위험 #a12737. 서체는 로컬 Malgun Gothic/Segoe UI, 본문 16px·상태 24px·제목 32px. 왼쪽 정렬, 긴 문장은 76ch 이내. 외부 폰트·이미지·라이브러리 없음.
처음 검토한 동일 크기 대시보드 카드 대신, 장비 배치와 실제 순서를 나타내는 연속 이송 레일을 핵심 요소로 선택했다. 대비·여백·텍스트 상태로 정보 위계를 만들고 꾸밈용 그래디언트/자동 애니메이션은 제거했다. 비교 브리프를 대입해 검토했을 때 이송 점유·불확실성·명령 증거가 핵심이므로 통계형 히어로를 배제했다.

```
[시뮬레이션 경고]                   [역할 선택]
[현재 단계 / 신규 배정 차단 원인 / 일시정지 상태]
[D1 감지·문·연결] — [R1 점유·연결] — [D2 감지·문·연결]
[작업 시작] [일시정지]     [명령 요청 / ACK / DONE]
[가상 제어기 입력과 장애 주입] [복구 조회 → 현장 확인 → 확정]
[명령 이력]                          [알람·감사 이력]
```

모바일에서는 레일과 제어 패널이 세로로 접힌다. 키보드 focus-visible, 모든 입력 label, 상태 aria-live, 색상과 텍스트 병기. 자동 움직임 없음. 구현 후 비평: 레일만 시각적으로 강조하고, 장애 주입은 별도 구역으로 배치해 작업 제어와 구분했다. 실제 브라우저 시각 검증 여부는 test-log.md에만 사실대로 기록한다.

## 논리 시스템 구성도

```
PC 경계 [HMI ⇄ 제어 서비스 ⇄ 로컬 저장소]
                   ⇅ 가상 TCP/JSON (양방향 요청/응답·상태)
            [D1 제어기] [D2 제어기] [R1 제어기]
독립 HW 경계 [안전 회로·비상정지] → 장비의 안전 동작
                         └→ PC 상태 표시·신규 배정 억제
```

HMI↔서비스는 내부 호출 제안, 저장소 인터페이스는 미정. 안전 입력을 PC가 변경하거나 HW 비상정지를 대체하지 않는다. 화면의 문/안전 버튼은 입력 시뮬레이션이다. 저수준 모터 제어·로봇 경로는 포함하지 않는다.

## 정상과 복구 여정

1. 작업 시작 → D1 요청 → ACK 주입 → DONE 주입. ACK만으로 공정 완료되지 않는다.
2. 이송 요청 → ACK → DONE. DONE으로 전달받은 합성 제어기 상태에서만 D1 비움/D2 채움으로 갱신한다.
3. D2 가공 요청 → ACK → DONE → 완료. 일시정지는 다음 요청만 막고 이미 실행 중인 작업을 정지시킨다고 표시하지 않는다.
4. 이송 중 연결 끊기 → 결과 불명·점유 유지. 재접속만으로 해결되지 않는다.
5. 제어기 조회에서 미완료이면 복구 확정 불가. 시험에서는 연결 후 DONE 응답을 주입하고 다시 조회한다. 현장 확인 체크와 유지보수 확정 후 다음 명령을 수동 요청한다. 물리 상태를 추정해 이송 재시도하는 버튼은 제공하지 않는다.

REQ-15 시나리오 기대: 정상 완료, 이송 두절 점유 유지, ACK 유실 2초 후 차단, 중복 명령 실행 수 불변, 역순 상태 불변, 재기동 복구 필요, 문/비상정지 시작 차단, 작업자 복구 거절, 저장 실패 명령 수 불변. 관측은 상태·이력 및 실제 inline JS를 실행하는 test.cjs 단언이다.
