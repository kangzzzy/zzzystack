# 개발 문서 작성·관리

프로젝트의 로드맵과 개발 산출물을 기본적으로 `docs/` 안에 Markdown으로 작성한다. 사용자가 지정한 경로·파일 형식과 프로젝트의 기존 문서 체계가 우선한다. 문서 작성 요청에 맞는 파일만 만들며 디렉터리와 문서 묶음을 일괄 생성하지 않는다.

## 문서 원본 찾기

프로젝트 지침, 기존 docs와 README의 문서 링크, 관련 코드·설정·이슈·PR·검증 기록을 확인한다. 같은 내용을 관리하는 원본이 있으면 갱신하거나 연결하고, 비슷한 이름의 문서를 중복 생성하지 않는다. 접근하지 못한 자료를 읽었다고 하거나 대화의 추측을 확정된 결정으로 쓰지 않는다.

독자와 문서 목적을 요청에서 파악한다. 내용이나 구조를 크게 바꾸는 미정 사항만 질문한다. 자료가 충분한 부분은 먼저 작성하고 확인이 필요한 사실은 명확히 표시한다.

## 산출물 선택

다음은 새 문서가 필요할 때의 예시다. 기존 이름과 구조가 있으면 그대로 따른다.

| 요청 | 기본 파일 예시 | 담을 내용 |
|---|---|---|
| 로드맵 | `docs/roadmap.md` | 목표, 현재 상태, 우선순위·단계, 범위·제외 범위, 의존성, 단계별 완료 조건 |
| 기술 설계 | `docs/architecture.md` | 현재 구조, 구성 요소·데이터 흐름, 제약, 대안과 선택 근거, 미결정 사항 |
| 개발 계획 | `docs/implementation-plan.md` | 변경 범위, 작업 순서·의존성, 검증 방법, 위험과 필요한 복구 방법 |
| 개발 현황 | `docs/implementation-status.md` | 기능별 구현·검증·출시 상태, 근거, 남은 작업과 막힌 부분 |
| 기술 결정 | `docs/decisions/NNNN-topic.md` | 배경, 검토한 대안, 결정 상태·근거·영향, 대체한 기존 결정 |
| 검증 결과 | `docs/verification.md` | 대상 버전·환경, 실제 실행 항목·결과, 실패·제약, 재현 근거 |

API나 운영 안내 등 다른 산출물도 요청에 맞춰 작성한다. API는 실제 인터페이스와 오류 처리를, 운영 안내는 실제 설정과 운영 절차를 근거로 쓴다. 예시 파일 이름이나 표의 열을 필수 서식으로 강제하지 않는다.

## 상태와 변경 관리

- 로드맵의 후보·예정·확정·완료를 구분한다. 사용자가 정하지 않은 일정·담당자·우선순위를 약속으로 만들지 않으며 제안은 제안이라고 표시한다.
- 구현, 테스트 통과, 병합, 배포를 구분하고 각각 확인한 근거를 연결한다. 코드나 문서를 작성했다는 사실만으로 기능 완료나 검증 통과를 선언하지 않는다.
- 기존 요구사항·기능 목록·이슈가 관리 원본이면 ID와 링크로 연결한다. 문서마다 서로 다른 완료 기준이나 진행 상태를 새로 관리하지 않는다.
- 실제 사건 날짜와 문서 갱신 날짜를 구분한다. 결정이 바뀌면 이전 기록을 지우기보다 대체 관계와 이유를 남긴다. 반복 갱신 시 같은 사건을 중복 기록하지 않는다.
- 관련 문서의 링크와 직접 영향받는 요약을 함께 갱신한다. 파일 이동·분할은 요청이나 실제 중복 해소에 필요할 때만 수행하고 기존 링크를 고친다.

새로운 제품·기술 판단이 필요한 부분은 문서화된 제안이나 미결정 사항으로 남긴다. 문서 작성 자체를 사용자 승인으로 간주하지 않는다. 별도 기획이나 구현도 요청받은 경우에만 해당 작업 스킬을 함께 사용한다.

## 확인과 완료

상대 링크·제목 앵커·파일 경로와 문서 간 상태 일치를 확인한다. 인용한 테스트·릴리스·코드가 해당 주장과 버전을 뒷받침하는지 점검한다. 확인하지 못한 근거나 실행하지 않은 검증은 한계로 남긴다.

문서가 늘어 탐색이 필요하면 기존 문서 목차를 갱신하거나 `docs/README.md`를 만들고 루트 README에서 연결한다. 한 파일만 작성하는 작업에 불필요한 목차를 만들지 않는다. 루트 README의 본문 작성·정리는 [readme](../verify-readme-base/SKILL.md), 개인 프로젝트 README 진행 이력은 [progress](../verify-progress/SKILL.md)의 범위를 따른다.

diff에서 요청 범위와 기존 기록 보존, 비밀값·개인정보 노출 여부를 확인한다. 작성·수정한 파일, 주요 내용, 확인 결과와 남은 결정만 보고한다. 문서 작성 요청만으로 이슈 상태 변경·커밋·push·PR·게시를 시작하지 않는다.
