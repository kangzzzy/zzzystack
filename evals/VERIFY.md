# 공통 평가 규칙

스킬 실험은 `evals/verify-<대상>/`에 모은다. 모든 임시 스킬의 폴더명과 SKILL.md의 `name`에는 `verify-` 접두어를 붙여 일치시킨다. 예를 들어 README 실험은 `evals/verify-readme/`와 `name: verify-readme`를 사용한다. 정식 스킬 이름은 유지한다.

실행 전에 이 문서와 해당 폴더의 `VERIFY.md`가 있으면 함께 읽고, 후보 `SKILL.md`를 적용한다. 스킬별 검증 계획은 실제 평가를 준비할 때 추가하며 빈 문서를 일괄 생성하지 않는다. 이 파일 이름만으로 호스트나 평가 실행기가 규칙을 자동 적용하지는 않는다. 평가 요청에 사용할 문서의 경로를 명시한다.

## 후보 생성 전 GitHub 조사

사용자가 임시 스킬 주제를 제시하면 생성·수정 전에 GitHub를 검색하고 후보를 먼저 제시한다. 사용자가 이번 조사 생략을 명시한 경우에만 건너뛴다.

- **인기 후보:** 조사한 관련 저장소 중 별 수가 높은 후보를 찾고, 별 수·확인 날짜·최근 유지보수 상태를 확인한다. 전체 GitHub에서 가장 인기 있다고 단정하지 않는다.
- **관련도 후보:** 별 수와 별개로 요청한 작업·산출물에 직접 맞는 저장소와 실제 스킬·프롬프트·템플릿 파일을 확인한다. 모음 저장소의 인기를 개별 스킬의 인기로 표현하지 않는다.
- 중복을 합쳐 3~5개 이내로 링크, 용도, 인기 근거, 관련성, 재사용 가능한 부분과 라이선스를 간단히 비교한다. 적합한 후보가 없거나 확인하지 못한 정보는 그대로 밝힌다.
- 추천 후보와 수정 방향을 제시하고 사용자와 선택·적용 범위를 정한 후 임시 스킬을 만든다. 조사만으로 설치·복사·생성을 시작하지 않는다.

## 파일 역할

- `VERIFY.md`: 입력, 실행 방법, 판정 기준과 비교 결론. 공통 내용은 이 문서에만 두고 스킬별 문서에는 차이만 적는다.
- `verify-<대상>/SKILL.md`: 실험할 후보 스킬. 평가용 레지스트리에 등록하되 기본 설치·활성화 대상에서는 제외한다.
- `verify-<대상>/results/`: 생성 결과와 실행 기록. 파일 이름이나 실행 ID로 구분하고 이전 결과를 덮어쓰지 않는다.

현재 CLI 평가기는 `.test-work/evals/<실행ID>/`에 원시 결과를 저장한다. 해당 실행을 사용할 때는 결과 경로를 실험 기록에서 연결한다. 이 폴더 정리는 기존 CLI 경로나 판정 로직을 변경하지 않는다.

현재 정식 유지 대상은 `i-have-adhd`와 `requirements`다. 나머지 기존 스킬 20개를 이 폴더로 옮겼으며, 기존 README 실험본 `verify-readme`도 유지한다. 이전 README 초안은 `verify-readme-base`로 보존한다. 내부 보조 자료인 `verify-documentation/references/docx/`는 별도 등록 스킬이 아니며 원본 이름을 유지한다. 위치 변경은 검증 완료 판정이 아니며, 레지스트리의 기존 평가 이력과 미검증 상태는 보존한다.

## 실행 조건

대상·원하는 결과·변경 가능한 파일을 먼저 정한다. 입력 프로젝트의 커밋과 미커밋 변경 또는 고정 사본, 요청 원문, 사용 스킬의 출처와 버전·해시, 날짜, 호스트·모델·추론 설정을 기록한다. 모르는 값은 `미기록`으로 표시한다.

후보를 비교할 때 입력·요청·모델·설정·채점 기준을 맞추고 이전 후보의 결과를 보지 않는 독립 실행을 사용한다. 전역 스킬·메모리 등의 적용 여부도 기록한다. 동일 대화에서 순차 작성한 결과나 조건이 다른 결과는 탐색용 비교로 표시한다. 반복 횟수는 목적에 맞게 정하고 기록하며 한 번의 좋은 결과를 일반적인 품질 보장으로 해석하지 않는다.

## 공통 검사

1. **요청 충족:** 지정한 산출물·경로·형식과 작업 범위를 지켰는지 확인한다.
2. **정확성:** 수치·상태·경로·명령·인용 근거를 입력 원본과 대조한다. 계획, 구현, 검증, 출시를 구분한다.
3. **형식과 연결:** 해당 산출물의 파싱·필수 구조·로컬 링크·앵커를 확인한다. 관련 없는 검사는 `해당 없음`과 이유를 적는다.
4. **변경과 보존:** 허용한 파일만 바뀌었는지, 기존 결과가 보존되는지 확인한다. 실제 비밀값을 결과에 넣지 않는다.
5. **판정 근거:** 실행한 검사·결과·미실행 항목·실패 이유를 남긴다. 형식 검사 통과와 사용자 관점의 품질 평가를 별도로 판정한다.

스킬별 기준은 위 검사에 추가한다. 공통 기준이 적용되지 않거나 사용자 지시와 다른 경우 해당 항목과 이유를 기록하며 묵시적으로 생략하지 않는다. 검사 기준과 절차는 결과를 본 뒤 유리하게 바꾸지 않는다.

## 기록과 종료

각 스킬의 `VERIFY.md`에 검증 전 과정의 짧은 이력을 유지한다. 실제 시험마다 날짜·입력/시나리오·검사 방법·결과·발견한 문제·미검증 항목·상세 결과 경로를 한 행으로 추가한다. 재시험은 이전 행을 지우지 않고 추가한다. 준비 완료, 실제 실행, 사용자 채택을 구분하고 실행하지 않은 시험은 통과로 기록하지 않는다.

실행 기록은 각 `results/`의 Markdown 파일에 입력·후보·환경·출력 링크·검사 결과를 적으면 충분하다. 자동 실행기가 이미 기록한 메타데이터는 경로로 연결해 중복 관리하지 않는다.

판정은 `통과`, `실패`, `미검증`, `해당 없음`으로 구분한다. 산출물 생성과 기술 검사 통과만으로 사용자 채택을 확정하지 않는다. 채택 여부와 이유는 스킬별 `VERIFY.md`에 기록한다. 실행 중 만든 임시 프로세스·작업 환경은 정리하되 산출물과 증거는 보존한다.
