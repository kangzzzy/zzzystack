# GitHub Issues 연결

프로젝트가 GitHub를 선택한 경우만 적용한다. 연결된 도구 또는 인증된 CLI를 확인한다. 접근 권한을 추측하거나 자격증명을 기록하지 않는다.

기획 확정 이후 등록이 승인되면 기존 이슈를 먼저 찾아 중복을 피한다. 이슈에는 작업 목적·범위·기능 ID·디자인/결정 링크·수용 기준·의존성·우선순위를 담는다. [작업 템플릿](../evals/verify-implementation/assets/task.md)을 사용한다.

개발 시작 정책을 확인하고 이슈를 작업 식별자로 사용한다. 순차 설정이면 활성 구현 이슈는 프로젝트당 하나다. 이슈와 PR·검증 결과를 연결하되 PR 생성/병합/배포 권한을 서로 동일시하지 않는다.

이슈 완료 조건에 따른 검증·문서 갱신 이후 종료한다. 구현 이슈 종료와 기능의 운영 출시 상태는 별도 기록한다. 연결 실패 시 로컬 초안과 미등록 상태를 남긴다.
