# 요구사항 분석

사용자가 분석 대상으로 지정한 원본 자료를 근거로 사용자 요구와 상세 요구를 정리한다. 사용자 대화는 작업 지시와 확인에 사용하며 수집자료로 자동 등록하지 않는다. 이전 요구사항 초안·생성된 산출물도 원본 근거로 자동 편입하지 않는다. 사용자가 해당 대화나 초안을 분석 자료로 명시한 경우에만 포함한다. [공통 원칙](../../shared/core.md)을 읽되, 이 스킬의 산출물·검토 순서는 아래 규칙을 따른다. [i-have-adhd](../i-have-adhd/SKILL.md)를 함께 읽고 응답과 검토용 MD의 가독성에 적용한다. 제품 방향이 미정인 부분만 별도 기획 단계에서 탐색한다. Plan 스킬은 현재 검증 중이므로 기본 설치에 포함되지 않는다.

## 저장 위치와 파일 관리

- 기준은 **현재 작업 중인 프로젝트**다. 스킬 설치 폴더나 harness 저장소에 프로젝트 자료를 저장하지 않는다. 요구사항 산출물은 프로젝트 루트 아래 `산출물/1_요구사항 분석/`에 저장한다.
- 원본 자료의 기본 위치는 **현재 프로젝트 루트의 `자료/`**다. 사용자가 지정한 분석 대상만 이 위치에서 읽기 전용으로 확인한다. 다른 원본 경로를 명시한 경우에도 해당 위치에서 직접 읽는다. **원본의 사본·보관본·백업·원문 추출 파일은 어느 위치에도 저장하지 않는다.** 원본의 내용·서식·파일명·위치를 변경하거나 주석·번호·교정 내용을 삽입하지 않는다. 원본에 접근할 수 없거나 복사 없이 읽을 수 없으면 그 제약을 알리고 자료 접근을 요청한다. 내용을 추측하거나 임의 복사로 우회하지 않는다.
- `프로젝트/산출물/1_요구사항 분석/`에는 아래 최신 MD 세 개와 승인 후 Excel을 저장하고, 생성 산출물의 백업은 이 폴더 아래 `백업/`에 둔다. 원본 자료·원본 사본은 넣지 않는다. `수집자료.md`는 `자료/` 원본의 경로와 확인한 사실을 기록하는 문서이며 원본 보관 폴더가 아니다.
- 검토용 최신 MD는 **`수집자료.md`, `사용자 요구사항.md`, `요구사항 정의.md` 세 개**로 고정하되 사용자 요구사항에 대한 중간 승인 없이 한 번의 작업에서 함께 생성한다. 별도 `원문_문단` 파일이나 출처·문단 색인 파일을 생성하지 않는다. 근거 위치는 `수집자료.md`에 함께 남긴다. Excel은 승인 후 `요구사항.xlsx`로 생성한다. 최신 파일명에 버전·날짜·최종 등의 접미사를 붙이지 않는다.
- 기존 생성 산출물을 변경하기 전에 `프로젝트/산출물/1_요구사항 분석/백업/<기존 이름>_v001.<확장자>`에 기존본을 보존한다. 백업은 최신본과 같은 폴더에 섞지 않고 반드시 그 아래 `백업/` 하위 폴더로 분리한다. 동일 이름의 다음 미사용 번호를 사용하고 백업을 덮어쓰지 않는다. 처음 생성하거나 내용이 같으면 백업을 만들지 않는다. 백업 대상은 이 스킬이 생성한 `수집자료.md`, `사용자 요구사항.md`, `요구사항 정의.md`, `요구사항.xlsx`로 한정한다. 분석 원본은 백업 대상이 아니다. 기존에 잘못 생성된 원본 사본은 자동 삭제·이동하지 말고 위치를 알린다.

## 검토와 승인 순서

1. 지정된 원본 자료를 읽기 전용으로 확인하고 **`수집자료.md`, `사용자 요구사항.md`, `요구사항 정의.md`를 한 번의 작업에서 모두 작성**한다. 사용자 요구사항 검토·승인을 기다리거나 요구사항 정의 생성을 미루지 않는다. 사용자 요구는 원문 그대로 인용하며 U ID를, 상세 요구에는 R ID를 부여한다.
2. 사용자 요구사항의 `연결 상세`를 실제 생성된 R ID와 요구사항 정의의 해당 항목으로 연결한다. U ID·원본 자료·수집자료를 연결 상세 대상으로 넣지 않는다. 동일 번호끼리 기계적으로 연결하지 말고 실제 대응 관계를 확인한다. 사용자 요구사항은 원문 기록으로 유지하며 수정 메모나 검토 상태를 받는 문서로 사용하지 않는다.
3. 수정이 필요하면 사용자는 **`요구사항 정의.md`의 비고에 comment**를 남긴다. 반영 요청 시 최신 파일을 다시 읽고 아래 메모 처리 규칙에 따라 해당 R 항목에 반영한다. 명시적인 사용자 수정 지시는 AI의 임의 해석과 구분하며 원문 인용인 사용자 요구사항의 내용을 자동으로 덮어쓰지 않는다. 상세 항목이 추가·삭제·이동되면 사용자 요구사항의 R 연결만 동기화한다.
4. “수정했어”나 메모 반영 요청은 내용 반영 요청이며 Excel 승인이나 개별 요구사항 상태 변경이 아니다. 필요한 질문은 대화에서만 한다. 최신 요구사항 정의에 대한 명시적 Excel 반영 승인을 받은 뒤 [Excel 양식](assets/requirements.xlsx)으로 `요구사항.xlsx`를 생성·갱신한다. 승인 전에는 기존 Excel을 유지한다.
5. 승인 대상과 일시는 요구사항 정의의 문서 수준에서 기록하고 MD·Excel의 내용·ID·왕복 링크를 대조한다. 이후 수정 시 사용자 메모와 직접 수정 내용을 보존하고, 변경된 내용을 Excel에 반영하기 전 승인을 확인한다. 일반적인 작업 시작 요청·침묵·이전 버전 승인을 현재 내용의 Excel 반영 승인으로 간주하지 않는다.
이 승인 절차는 프로젝트 요구사항 산출물에 적용한다. 사용자가 스킬 자체나 빈 양식의 수정을 요청한 경우에는 요청한 스킬·양식 수정을 수행한다.

## MD 가독성과 번호 체계

- 사용자 요구사항에는 문서·항목 상태를 표시하지 않는다. 요구사항 정의에서만 필요한 현재 상태를 짧게 표시한다. 한 요구사항은 `제목(이름 · ID) → 요구 내용 → 참고 목록` 순서로 보여 준다. 사용자 요구 내용은 아래 원문 인용 규칙이 짧은 문장·요약 선호보다 우선한다.
- 세 검토용 MD는 **표 없이 제목·본문·목록**으로 작성한다. 요구사항 항목 사이에는 빈 줄과 Markdown 구분선(`---`)을 넣고 구분선 앞뒤에도 빈 줄을 둔다. 연결 등 부가 정보는 짧은 글머리 목록으로 표시한다. 상태는 요구사항 정의에만 표시한다. 수집자료는 아래 자료별 형식을 따른다.
- 산출물에 AI가 작성한 `확인 필요` 문구·질문·추가 해석·추측·권고를 넣지 않는다. 기존 생성 산출물을 수정할 때도 이러한 추가 내용을 제거한다. 원문 인용 자체에 포함된 표현은 교정하거나 삭제하지 않는다. 중첩 목록과 과도한 굵은 글씨를 피한다. 읽기 쉽게 나누되 실제 요구사항이나 근거를 생략하지 않는다. 이 표시 규칙은 MD에 적용하며 Excel의 표·열 구성은 유지한다.
- **확정된 ID 체계:** 사용자 요구는 `U-01`, `U-02`, 상세 요구는 `R-01`, `R-02` 형식이다. 두 자리 이상으로 표시하며 100번째는 `U-100` 또는 `R-100`이다. 상세 ID에 상위 요구 번호를 넣지 않는다. U ID는 기존 번호를 유지하며 새 사용자 요구만 기존 최대 번호 다음으로 추가한다.
- **요구사항 정의를 수정할 때마다 R ID 전체를 문서의 최종 배치 순서대로 `R-01`부터 빠짐없이 다시 배정한다.** 본문 수정·comment 반영·추가·삭제·정렬 모두에 적용한다. 주제가 바뀌어도 번호를 다시 시작하지 않고 문서 전체에서 연속 번호를 사용한다. 기존 R 번호 유지나 삭제 번호 재사용 금지 규칙은 적용하지 않는다.
- 재번호 전 항목과 상위 U의 대응 관계를 작업 중에 보존하고, 수정 완료 후 새 R ID로 사용자 요구사항의 연결 상세·MD 앵커·왕복 링크를 함께 갱신한다. 같은 숫자나 변경된 제목만으로 항목을 연결하거나 순차 문자열 치환으로 ID를 충돌시키지 않는다. U ID와 사용자 요구 원문은 재번호하지 않는다. 중복·누락·이전 R 링크 잔존과 잘못된 U 연결을 검사한다. 이전 버전은 산출물 백업으로 보존하며 별도 대응표 파일이나 비고 이력은 만들지 않는다. Excel은 반영 승인 후 최신 R ID로 동기화한다.
- **목차·주제 제목에는 번호를 붙이지 않는다.** `1.`, `1.1`, `1.2.3` 같은 제목 접두사를 쓰지 않는다. 사용자 요구 제목은 `## 지난 작업 찾기 · U-01`, 상세 요구 제목은 `## 날짜별 조회 · R-01`처럼 이름을 먼저 표시한다. 주제별 하위 제목이 필요하면 `###`를 사용하되 번호는 붙이지 않는다. 수집자료의 제목에도 일련번호를 붙이지 않는다.
- 기존 요구사항 산출물을 작성·수정할 때 이전 ID 체계도 U/R 체계로 전환한다. 사용자에게 같은 체계 선택을 다시 묻지 않는다. 기존 U ID는 보존하고 R ID는 위의 전체 재번호 규칙을 따른다. 변경 전 백업으로 이전 ID를 보존하고 MD의 상위·상세 연결과 앵커를 함께 갱신한다. 사용자 요구사항 비고에 이전 ID나 변경 이력을 기입하지 않는다. 원본 자료의 ID는 변경하지 않는다. Excel은 MD 승인 후 같은 ID와 링크로 반영하고, 승인 전에는 기존 Excel을 유지하며 반영 대기를 표시한다. 별도 색인 파일은 만들지 않는다.
- `수집자료.md`는 **자료별 제목 → 자료 위치 → 확인된 사실 목록** 순서로 작성한다. 자료 위치에는 원본 경로·URL을 한 번 적는다. 사실을 요약한 항목은 다음 줄에 `위치:`로 페이지·절·시트·셀 등 근거 위치를 붙인다. **원문 그대로 인용한 항목에는 개별 위치를 생략**한다. 이 경우에도 자료별 원본 위치는 유지한다. 서로 다른 자료의 사실을 합치지 않는다. **구분선은 자료 사이에만** 넣는다. 원문 전체 복제나 문단별 일련번호 색인을 만들지 않는다. 요약 근거의 위치를 확인할 수 없으면 미확인으로 표시한다.
- 기존 프로젝트의 `요구사항.md`를 세 파일 체계로 전환할 때는 먼저 백업하고 내용을 나눈 뒤 누락과 링크를 확인한다. 기존 원문·색인 파일은 새로 만들거나 갱신하지 않으며 사용자 자료를 임의 삭제하지 않는다.

## 사용자 요구 원문 인용

- `사용자 요구사항.md`의 요구 내용은 **원문 표현 그대로 인용**한다. 요약·의역·문장 확장·맞춤법 교정·말투 변경을 하지 않고, 주어·목적·조건·기능을 덧붙이지 않는다. 가독성을 이유로 인용문을 다시 쓰지 않는다. Markdown에서는 인용 블록(`>`)으로 표시하며 인용 내부에 강조 표시나 설명을 삽입하지 않는다.
- 요구사항명도 원문의 제목이나 짧은 연속 구절을 사용한다. 새 의미를 가진 제목을 창작하지 않는다. 원문에서 필요한 문장·구절을 선택하되 문맥을 왜곡하지 않고, 떨어진 구절을 하나의 발언처럼 이어 붙이지 않는다. 여러 발언은 인용 블록을 각각 구분한다.
- 원문을 직접 확인해 인용문과 대조한다. **사용자 요구사항에는 인용 출처를 표시하지 않는다.** 자료명·파일 경로·페이지·문단·셀·URL·수집자료 링크·각주를 본문이나 참고 목록에 덧붙이지 않는다. 출처 정보는 수집자료에서만 관리한다. 정확한 표현을 확인할 수 없으면 해당 내용을 요구사항으로 작성하지 않는다. 원문 확인에 필요한 질문은 대화에서만 하고 산출물에는 남기지 않는다.
- 이 규칙은 승인 후 Excel의 사용자 요구사항 명세서 `요구사항명`·`요구 내용`에도 적용한다. `요구사항 정의.md`와 요구사항 정의서도 원문에 명시된 상세 내용만 정리하고 상위 U ID로 연결한다. AI의 해석으로 요구사항을 확장하지 않는다. 수집자료의 사실 요약과 사용자 요구의 직접 인용을 혼동하지 않는다.

## 산출물 구성

- **요구사항 정의에도 추가 해석을 넣지 않는다.** `요구사항 정의.md`와 Excel 요구사항 정의서의 본문·근거·비고·주석 어디에도 AI가 만든 `확인 필요`·질문·추측·권고를 기입하지 않는다. 기존 생성 산출물을 수정할 때도 제거한다. 원문에 명시된 상세 내용만 정리한다.
- **요구사항 정의에는 `근거` 항목을 만들지 않는다.** `요구사항 정의.md`와 Excel 요구사항 정의서에서 근거 제목·칸·목록을 제거하고 `근거: U-01`도 표시하지 않는다. 비고·주석으로 옮기지 않는다. Excel의 `상위 사용자 요구 ID` 자체에 왕복 연결 링크를 넣으며 별도 근거 필드나 `사용자 요구 이동` 열을 만들지 않는다.
- **사용자 요구사항의 비고는 항상 공란**으로 둔다. 사용자 요구사항은 원문 기록이며 수정 comment는 요구사항 정의에서만 받는다.
- **요구사항 정의의 비고는 사용자 수정 comment용**이다. AI의 최초 작성과 수정 반영 완료 후에는 공란으로 둔다. 반영 요청 시 최신 파일과 비고를 먼저 읽고 기존본을 정해진 산출물 백업 위치에 보존한 뒤 해당 R 항목에 메모 지시를 반영한다. 반영 결과를 확인한 메모는 최신본 비고에서 지운다. 읽지 않고 삭제하거나 메모 자체를 본문·출처로 복사하지 않는다. 모호하거나 미반영된 메모는 대화로 확인하고 해결 전까지 보존한다.
- 두 문서의 비고에 AI가 `미정`, `없음`, `-`, 변경 이력·처리 완료 문구를 넣지 않는다. 메모 반영은 문서 승인이나 개별 요구사항 상태 변경을 의미하지 않는다. 사용자 지시를 반영해도 분석 원본은 수정하지 않는다. Excel의 실제 갱신은 승인 절차를 따른다.
두 시트 모두 5행의 부가 설명은 비워 둔다. 상세 시트의 별도 `사용자 요구 이동` 열은 제거한다. B열 링크는 실제 상위 U ID를 표시값으로 지정하고 현재 R ID로 첫 시트 F열을 조회해 대응 셀로 이동한다. B셀 자신을 수식의 입력으로 참조하지 않는다. 빈 양식의 B열은 비워 두고 실제 작성 시 U ID 링크를 채운다.

Excel에는 다음 두 시트만 둔다. `검토 및 범위` 시트는 만들지 않는다.

| 시트 | 열 순서 |
| --- | --- |
| 사용자 요구사항 명세서 | 사용자 요구 ID, 요구사항명, 요청자·사용자, 요구 내용, 요구 출처, 요구사항 정의서 ID 이동, 비고 |
| 요구사항 정의서 | 상세 요구 ID, 상위 사용자 요구 ID, 분류, 요구사항명, 상세 정의, 상태, 비고 |

- 사용자 요구사항의 출처 표시는 MD와 Excel 모두 생략한다. 기존 Excel 양식의 `요구 출처` 열은 비워 두며 비고·주석·링크로 출처를 우회 표시하지 않는다. 자료 위치와 요약 근거는 `수집자료.md`에서만 관리한다. 상세 요구는 상위 U ID로 연결한다.
- **연결 검사·연결 수·우선순위는 모든 시트에서 제외**한다. 숨김 열·보조 시트·수식·안내문으로도 다시 넣지 않는다. ID와 링크의 무결성은 작성 도구에서 확인하고 산출물에 검사 열을 추가하지 않는다.
- **입력·출력, 조건·예외, 수용 기준, 검증 방법은 요구사항 문서의 필드로 작성하지 않는다.** 해당 설계 내용은 별도 설계 단계에서 구체화한다. 설계 스킬은 현재 검증 중이므로 기본 설치에 포함되지 않는다. 사용자가 명시한 요구나 제약 자체는 상세 정의에 보존하고, 설계 결정을 새로 덧붙이지 않는다. MD도 같은 필드 범위를 따른다.
- **요청자는 항상 비워 둔다.** 사용자 요구사항의 `요청자·사용자`는 MD·Excel 모두 빈 값으로 유지한다. 자료에 이름이 있어도 채우지 않으며 `미정`, `없음`, `-` 같은 대체 문자도 넣지 않는다. MD에서 해당 항목을 표시한다면 라벨 뒤를 비우고, Excel은 열을 유지하되 셀 값을 비운다. 사용자 요구사항 비고는 공란이며 수정 메모는 요구사항 정의 비고에서만 처리한다. 생성 산출물을 수정할 때도 이 규칙을 적용하며 분석 원본은 변경하지 않는다.
- 사용자 요구사항에서는 상태 필드·목록·Excel 열을 제거한다. 요구사항 정의의 상태는 `초안·검토 중·확정·보류·제외`, 분류는 `기능·품질·업무 규칙·제약` 드롭다운으로 선택한다. 목록 밖 값은 차단하며 요구 내용·상세 정의는 원문 인용 및 필드별 규칙을 따른다. AI는 비고를 채우지 않는다. 요구사항 정의 비고의 사용자 수정 메모는 위 절차로 처리한다.

## 행과 이동 링크

- 첫 시트에서 사용자 요구 하나를 한 묶음으로 작성한다. **요구사항 정의서 ID 이동(F)만 상세 항목별로 나누고, 나머지 공통 열(A:E, G)은 묶음 안에서 세로 병합하여 한 번만 표시**한다. F열은 기존 연결 상세 ID와 이동 기능을 통합한 열이며 별도 `상세 이동` 열은 만들지 않는다. 같은 사용자 요구 ID와 공통 내용을 반복하지 않는다.
- 빈 양식은 요구사항 50개에 연결칸 4개씩 예약한다. 실제 산출물은 상세 수에 맞춰 묶음 크기를 조정하고, 4개로 제한하지 않는다. 상세가 없으면 한 행을 유지한다. 행 변경 시 병합·수식·드롭다운·서식 범위를 함께 갱신한다.
- 첫 시트 F열은 **R ID 자체(예: `R-01`)를 표시하는 클릭 가능한 내부 링크**로 작성한다. 이동 대상은 요구사항 정의서의 해당 R 행이다. 각 R 항목마다 한 셀·한 링크를 사용하고 링크처럼 보이는 텍스트만 넣지 않는다. 상세 시트의 **상위 사용자 요구 ID(B) 자체를 클릭 가능한 U ID(예: `U-01`)로 표시**하고 해당 U·R에 대응하는 첫 시트 F셀로 돌아간다. `이동`만 표시하거나 모든 상세를 첫 행으로 연결하지 않는다.
- F열에는 실제 연결할 R ID를 확정한 뒤 `HYPERLINK` 수식을 생성한다. 예: `=HYPERLINK("#'요구사항 정의서'!A"&(MATCH("R-01",'요구사항 정의서'!$A$8:$A$207,0)+7),"R-01")`. F셀 자체를 입력값으로 참조하여 순환 참조를 만들지 않는다. 링크 표시값은 R ID와 정확히 같게 유지하여 역방향 ID 조회가 가능하게 한다. 빈 양식의 F열은 연결할 ID가 없으므로 비워 두고 실제 문서 작성 시 링크를 채운다. 이 열에는 입력 드롭다운을 중복 적용하지 않는다. 번호·행 수 변경 시 수식의 ID·범위와 왕복 링크를 갱신한다.
- 첫 시트는 병합 문서이므로 Excel 표나 개별 행 정렬을 사용하지 않는다. 요구사항 묶음 전체를 이동한다. 상세 시트는 Excel 표를 유지한다. 중복 ID·누락·잘못된 상위 U ID와 정렬 후 왕복 대상은 작성 도구에서 검증한다.

완료: 사용자 승인 전이면 **MD 검토 대기**, 승인 후에는 승인된 내용·ID가 일치하는 두 시트와 링크 검증 결과를 보고한다. 빈 양식을 분석 완료로 보고하지 않는다. Excel 도구가 없으면 MD를 보존하고 Excel 미생성 상태를 알린다. 다음 단계는 설계이며 요청한 범위까지만 진행한다.
