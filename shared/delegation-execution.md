# 스킬을 별도 작업자에게 위임하기

현재 호스트에 따라 [Claude Code](../hosts/claude-code.md) 또는 [Codex](../hosts/codex.md)를 읽는다. 전문성은 각 작업 스킬의 references에 있으며 고정 agent 등록을 요구하지 않는다.

## 실행을 분리하는 조건

일반 기획·설계·구현은 현재 세션에서 해당 스킬과 필요한 전문 지침을 적용한다. 별도 맥락이 필요한 탐색, 범위가 분리된 구현, 독립 판단·검토에만 호스트의 범용 agent 또는 별도 세션을 사용한다. 독립 검토는 작성자와 다른 실행이어야 한다. 역할이 여러 개라는 이유만으로 agent를 각각 생성하지 않는다.

## 실제 위임

1. 현재 작업 스킬과 프로젝트의 확정된 역할 배정에서 필요한 전문 지침을 선택한다. 관련 없는 지침은 읽히지 않는다.
2. 호스트에서 실제 사용 가능한 범용 agent/별도 세션, 권한과 작업 범위를 확인한다. 고정 이름 `backend`나 `reviewer`가 설치돼 있다고 가정하지 않는다.
3. 아래 전달 양식으로 작업 스킬·전문 지침·[공통 원칙](core.md)·이 문서의 실제 경로와 작업 범위·기준·산출물·한도를 전달한다. 작업자는 실행 전에 관련 문서를 읽는다. 파일 접근이 불가능한 별도 세션에는 필요한 내용을 포함한다.
4. 검토자는 대상 결과물을 수정하지 않는다. 호스트가 작업별 read-only 권한을 지원하면 적용한다. 지원하지 않으면 비수정 지침과 허용 검증 범위를 명시하고 권한이 강제된다고 주장하지 않는다. 비파괴 검증에 필요한 임시 출력은 허용 범위 안에서만 만든다.
5. 위임 자체가 불가능하면 기획·작성은 현재 세션에서 수행할 수 있다. 독립 검토는 패킷을 저장하고 `review_pending`으로 남긴다. 이미 검토자로 위임받은 실행은 직접 검토하며 다른 검토자를 다시 생성하지 않는다.
6. 부모가 결과와 근거를 원래 완료 조건에 대조하고 다음 스킬 또는 사용자 판단으로 연결한다. 모델을 임의로 강제하거나 승인 범위 밖 병렬 실행을 시작하지 않는다.

## 작업별 지침 선택

### 작업자 규칙

- 필수 입력이 빠졌으면 부모에게 요청한다. 공유 파일 시스템에서 다른 담당자의 변경을 되돌리지 않으며 지정된 범위를 지킨다.
- 현재 단계만 수행한다. 기획·설계가 구현 시작을 뜻하지 않으며 작성자는 자기 결과를 독립 승인하지 않는다.
- 검토자는 대상 결과물을 수정하지 않는다. 허용된 비파괴 검증을 수행하고 권한이 없으면 미검증 항목을 반환한다.
- 사용자와 부모가 승인한 범위, 호스트 권한과 한도를 따른다. 하위 작업자를 다시 생성하기보다 협의 사항을 부모에게 전달한다.
- 변경·발견, 검증 근거, 미검증·위험, 판단 필요 사항과 다음 단계를 반환한다. 검토에는 대상 버전과 작성자와 다른 검토 세션 식별을 포함한다. 주요 변경·충돌·한도 도달은 보류 사유로 보고한다.

### 전달 양식

필요할 때 작업 기록이나 위임 메시지에 아래 항목을 작성한다. 별도의 빈 프로젝트 파일은 자동 생성하지 않는다.

- 작업 ID / 작업 스킬·전문 지침·공통 원칙·이 문서의 경로 / 실행 식별자:
- 목표·범위·제외 범위 / 입력 원본 위치:
- 기능·설계·결정 기록 / 완료 조건:
- 프로젝트 루트 / 허용 파일·행동 / 금지·승인 대기:
- 산출물·반환 형식 / 도구·재시도·자원 한도:
- 검토인 경우 대상 버전·작성자 식별·검증 근거:

부모의 결론을 정답으로 제시하지 않는다.

### 전문 지침 연결

| 작업 스킬 | 필요한 경우 적용하는 전문 지침 |
|---|---|
| [plan](../evals/verify-plan/SKILL.md) | 웹 기획; UX·아키텍처 쟁점 협의 |
| [design](../evals/verify-design/SKILL.md) | 웹 아키텍처·UX/UI·DB 설계 |
| [implementation](../evals/verify-implementation/SKILL.md) | 프런트엔드·백엔드·DB |
| [review](../evals/verify-review/SKILL.md) | 검토자 기준; QA·보안 |
| [release](../evals/verify-release/SKILL.md) | 배포·서비스 운영 |
| [investigate](../evals/verify-investigate/SKILL.md) | 문제 영역의 전문 지침; 부모가 결과 취합 |
| [handoff](../evals/verify-handoff/SKILL.md) | 부모가 기록 종합; 새 실행은 필요한 경우만 |

웹 이외 분야는 책임·입력·산출물·검증 기준을 먼저 정한다. 프로젝트당 순차 정책과 전체 자원 한도는 호스트가 지원하는 동시 실행 수보다 우선한다.
