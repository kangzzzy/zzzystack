# 자동화 셀 비교 시험 입력 — v1

사용자 요청: “1번 2개와 로봇이 소통하는 자동화 SW 예제”. 아래 세부 조건은 실제 장비 사양이 아니라 비교를 위해 만든 가상 시험 조건이다. 실제 동작·안전 검증이나 현장 배포를 의미하지 않는다.

## 대상과 경계

셀 제어 PC가 소형 가공 장비 D1·D2, 이송 로봇 R1과 통신한다. 각 장비에는 모터·공작물 감지 센서·문 상태 입력이 있고 공통 HMI에서 상태를 감시한다. 셀 SW는 작업을 배정하며 저수준 모터 제어·로봇 경로 계획은 각 제어기가 맡는다. 안전 회로와 비상정지는 독립 HW가 담당하고 셀 SW는 상태를 표시하고 새 명령을 억제한다. 가상의 TCP/JSON 어댑터를 사용한다. 실제 프로토콜·주소·레지스터·제어 주기·안전 정지 시간은 미정이며 만들지 않는다.

## 요구사항

| ID | 조건 |
|---|---|
| REQ-01 | 한 사이클은 D1 가공 → R1이 D1에서 D2로 이송 → D2 가공 → 완료 순서다. |
| REQ-02 | D1·D2 상태는 IDLE, PROCESSING, READY, FAULT, OFFLINE. R1 상태는 IDLE, BUSY, FAULT, OFFLINE이며 컨트롤러가 실제 상태의 원본이다. |
| REQ-03 | 이송은 D1 READY·공작물 있음, D2 IDLE·비어 있음, 로봇 IDLE, 관련 문 닫힘, 안전 신호 정상일 때만 요청한다. 로봇 명령 전 점유를 확보하고 통신으로 실제 완료를 확인할 때까지 중복 배정을 막는다. |
| REQ-04 | 모든 변경 명령은 command_id, cycle_id, target, type을 가진다. ACK는 수신 확인이고 DONE은 실제 완료다. 같은 command_id의 중복 수신은 물리 작업을 재실행하지 않고 이전 결과를 돌려준다. |
| REQ-05 | 가상 시험의 heartbeat 주기는 1초, 수신 3초 경과 시 OFFLINE, ACK 대기는 2초다. 작업 DONE 시간은 장비별 미정이다. 이 값은 실시간 제어/안전 성능 보장이 아니다. |
| REQ-06 | ACK timeout이나 이송 중 통신 두절은 결과 불명 상태다. 이동 명령을 자동 재전송하지 않고 신규 배정을 막아 조회·현장 확인 후 복구한다. |
| REQ-07 | 재접속과 앱 재기동은 자동 재개를 유발하지 않는다. 저장된 cycle/command 상태와 제어기 상태를 대조하고 권한 있는 사용자가 복구를 확정한다. |
| REQ-08 | HMI는 D1·D2·R1 상태, 연결, 센서, 현재 사이클 단계, 알람, 명령 요청/ACK/DONE을 구별해 표시한다. 색상 외 텍스트도 제공한다. |
| REQ-09 | 작업자는 시작·일시정지를 할 수 있다. 복구 확정은 유지보수 역할만 가능하다. 일시정지는 신규 명령 배정을 막는 기능이며 HW 비상정지와 구분한다. |
| REQ-10 | 상태가 오래됐거나 통신이 끊겼거나 안전 입력이 비정상이면 시작/이송을 비활성화하고 원인을 표시한다. UI 버튼뿐 아니라 제어 서비스가 검사한다. |
| REQ-11 | 설정, cycle/command 이력, 알람·감사 이벤트를 로컬 저장한다. command_id는 유일해야 한다. 업데이트 중 중단돼도 명령 기록이 부분 저장되지 않아야 한다. 보존 기간은 미정이다. |
| REQ-12 | 측정값은 단위·측정 시각·유효성을 포함하고, 메시지는 스키마 버전·발신자·순번을 포함한다. 지연/역순 상태가 최신 상태를 덮어쓰지 않도록 한다. |
| REQ-13 | 오류/알람을 지웠다는 사실만으로 장비가 정상 또는 물리적으로 복구됐다고 간주하지 않는다. 위험/고장 원인 해소와 상태 대조가 필요하다. |
| REQ-14 | 시스템 구성도에는 PC의 HMI·제어 서비스·저장소, 장비 D1/D2, 로봇 R1, 독립 안전 회로의 경계를 표시한다. 링크의 방향·프로토콜 및 미정인 부분을 명시한다. |
| REQ-15 | 정상 사이클, 이송 중 끊김, ACK 유실, 명령 중복, 역순 메시지, 앱 재기동, 문 열림/비상정지, 권한 없는 복구, 저장 실패를 테스트한다. 기대 결과와 관측 방법을 정한다. |
| REQ-16 | 모든 산출물에서 확인된 입력·설계 제안·미정을 구분하고 요구사항 ID를 연결한다. 센서/물리 상태를 SW의 추측으로 덮어쓰지 않는다. |

## 공통 출력 제한

비교 1차는 Markdown 설계 문서와 필요 시 외부 의존성 없는 HTML 시뮬레이션으로 한다. 최종 Word/Excel/Figma 양식 적합성과 실제 장비 제어는 이번 시험 범위 밖이다. 산출물에서 명확히 밝힌다. 실제 프로토콜 채택이나 특정 프레임워크 도입을 결정하지 않는다.
