# 신규 프로젝트 온보딩

## 목표와 요구사항

대상 위치, 해결할 문제, 사용자, 주요 사용 흐름, 성공 기준, 제약과 제공 자료를 정리한다. 이미 답한 내용을 다시 묻지 않는다. 제품 목표나 수치·일정·예산을 임의로 확정하지 않고 제안과 가정을 구분한다.

실제 요구사항이 있으면 requirements 지침으로 기능·비기능 요구사항, 출처, 우선순위, 확인 가능한 완료 기준을 정리한다. 첫 구현에 포함할 MVP와 제외할 범위를 구분한다. 권한·실패·잘못된 입력 등 핵심 흐름의 예외를 필요한 만큼 확인한다. 다음 행동에 영향을 주지 않는 미정 사항은 질문 목록으로 남긴다.

## 기술 선택과 최소 골격

기존에 선택한 기술·템플릿·폴더 규칙을 우선한다. 선택하지 않았다면 제약에 맞는 후보와 추천 근거를 제시하고 실제 선택을 확인한다. 응답이 없다는 이유로 중요한 기술 결정을 확정하지 않는다. 선택 대기 중에는 기술과 무관한 요구사항·범위 정리를 진행한다.

대상 위치와 기술 선택이 정해지면 기본 온보딩 범위에서 실행 확인에 필요한 최소 골격과 로컬 설정을 준비한다. 비어 있지 않은 폴더는 먼저 조사하고 기존 파일을 덮어쓰지 않는다. 업무 기능은 후속 개발 계획에 남긴다.

## 환경 준비와 검증

공통 코드 참조의 환경 보존·실행·기록 절차를 따른다. 런타임, 패키지 관리자, 필요한 환경변수 이름, 로컬 서비스와 실행 명령을 정한다. 대표 페이지·응답·CLI 결과를 확인한다. 골격 실행 성공은 앞으로 구현할 업무 기능의 정상 동작을 증명하지 않는다.

## 인계

MVP 경계, 선택한 기술과 이유, 가정·미정 사항, 준비한 환경과 실제 실행 근거, 첫 개발 작업의 순서와 완료 기준을 기존 지식 기록에 남긴다. 기술이나 대상 위치가 정해지지 않았다면 분석 결과를 전달하고 골격 생성·실행 확인이 어떤 결정에 막혀 있는지 명시한다.
