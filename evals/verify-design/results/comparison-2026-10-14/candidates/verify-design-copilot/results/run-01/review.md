- 검토자: /root/review_evals_move. 날짜: 2026-10-14.
- 대상: `.test-work/design-comparison/verify-design-copilot/`의 requirements.md, architecture.md, test-log.md, check.ps1.
- 범위: 신규 요구사항 기반 아키텍처 문서 검토. 구현 코드가 없다는 전제에서 평가했으며 다른 후보와 비교하거나 원본 스킬 성능의 인과적 결론을 내리지 않았다.
- 판정: 요구사항과 복구 정책의 정합성 확인이 필요한 사항 1건. 실행 검증 과장은 확인하지 못했다.

## 1. 결과 불명 복구의 현장 확인을 조건부로 완화함

**기준:** REQ-06은 ACK timeout 또는 이송 중 통신 두절을 결과 불명으로 취급하고 조회·현장 확인 후 복구하도록 요구한다.

**문서 근거:** architecture.md §5 시나리오 4는 '센서와 물리 공작물 위치 대조 → 불명확하면 현장 확인 → 유지보수 역할로 해결 근거 확정'이라고 설명한다. 즉 조회·센서 결과가 명확하면 현장 확인 없이 확정하는 경로를 허용하는 문구다.

**영향:** 필수 현장 확인을 불명확할 때만 필요한 절차로 해석할 수 있다. 이는 DB나 프로토콜 선택과 같은 합당한 상세 미정이 아니라 요구사항에서 정한 복구 게이트의 변경이다. ACK 유실/이송 두절 복구에는 현장 확인을 명시적으로 요구하거나, 조건부 생략 정책을 별도의 사용자 승인 대상 제안으로 구분해야 한다. T02/T03에 현장 확인 전 복구 거부 관측을 추가하면 검증 가능하다.

**범위:** 문서의 조건문을 근거로 한 설계 정합성 지적이며 실제 구현에서 우회가 발생했다는 주장은 아니다. 물리 위치 대조를 필수 현장 확인과 동일한 의미로 의도했다면 그 의미를 명확하게 적으면 해결된다.

## 적절하게 남겨 둔 미정

실제 프로토콜/주소, DB와 IPC, 인증 구현, 장비 결과 조회 계약, 세션 세대, 보존 기간, DONE 제한시간을 미정으로 남긴 것은 신규 아키텍처 단계에 적절하다. 담당 역할과 구현 전 확인 조건을 제시하며, freshness 미확정 시 시작 금지 및 부팅 RECOVERY_REQUIRED 등 차단 정책도 명시한다. 실행 구현이 없다는 이유만으로 이를 코드 결함으로 판정하지 않는다.

전송 전 의도·점유 원자적 기록, 전송과 DB 사이의 불확실 구간, DONE 저장 실패 후 다음 배정 차단, 늦은 ACK/DONE의 자동 재개 금지, 물리 상태와 투영/복구 상태의 구분은 문서상 서로 일관된다.

## 검증 재현과 과장 여부

원본 3개(requirements.md, architecture.md, check.ps1)를 이 검토 폴더에 복사하고 사본 check.ps1을 실행했다. 원본 결과를 덮어쓰지 않았다.

실제 결과는 [check-results.json](check-results.json): 요구 ID 참조 16개, 시험 행 10개, 추적 요구 15개(REQ-15 자체 제외), Mermaid 노드 10개, 정규식으로 검출한 유효 끝점 링크 18개, 구조 검사 PASS.

이 검사는 정규식 기반 선언/참조·표 구조 검사다. Mermaid 파싱/렌더링, 의미론, 도표 레이아웃을 검증하지 않는다. test-log.md가 이를 명시하고 T01~T10을 향후 행동 시험으로 구분하므로 실제 실행 검증을 과장한 것으로 판단하지 않는다. 전체 요구 충족 여부는 참조 개수만으로 입증되지 않는다.

실제 시뮬레이터·브라우저·Mermaid 렌더러·TCP·인증·저장 장애·실장비·HIL·안전 동작 시험은 수행하지 않았다. 네트워크·설치·재위임 없이 검토 파일만 `.test-work/review-copilot/`에 보존했다.
