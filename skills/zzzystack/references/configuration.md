# 프로젝트 설정과 실행 상태

[설정 예시](../assets/project.example.json)는 새 프로젝트의 초기값이다. CLI `init`은 이 예시를 프로젝트 `.zzzystack/config.json`으로 복사하고 프로젝트명만 채운다. 실제 프로젝트 설정은 설치·업그레이드로 덮어쓰지 않는다. 스키마 버전 1과 기존 키·기본값을 유지한다.

| 설정 | 의미와 적용 범위 |
|---|---|
| project_name, roles, tools | 프로젝트 식별·전문 역할 배정·사용할 도구. roles는 고정 agent 등록 이름이 아니며 기존 역할 식별자를 그대로 사용할 수 있다. |
| approved, approvals | 프로젝트에서 합의한 정책. 승인 사실은 실제 사용자 지시·기록으로 확인하며 값 자체로 호스트 권한이 늘어나지 않는다. |
| workflow | 작업·문서 원본 위치, 기획 이후 시작 의도, 활성 작업 한도. 작업 스킬이 정책을 따르지만 별도 실행기가 프로젝트 잠금이나 자동 시작을 구현하지는 않는다. |
| limits | 재시도·비용 한도와 계량 방식의 선언. CLI는 값의 유효성을 검사하며 비용 측정·강제 중단을 수행하지 않는다. |
| automations | 활성화 의도, 시간대·보고 시각·우선순위·재시작 정책. 예약·재개·외부 전송은 호스트 실행기를 별도로 연결해야 한다. |

`check-project`는 설정 형식을 검증한다. `automation progress|report|resume`은 프로젝트 설정을 확인하고 호스트용 프롬프트를 출력한다. 두 명령 모두 예약·실행·배포·전송을 시작하지 않는다. 자동화 활성화 설정에는 승인된 정책과 명시적 한도·계량 방식이 필요하지만, 검증 통과가 실행기 준비를 증명하지는 않는다.

실제 실행 ID·로그·검증 결과·잠금·누적 사용량은 프로젝트 기록이나 실행기가 관리하는 상태다. 이를 배포되는 설정 예시에 기록하지 않는다. 기존 `.zzzystack/config.json`이나 지식·작업 기록이 있으면 해당 원본을 재사용한다. `init`을 다시 실행해 덮어쓰지 않는다.
