# 코드 리뷰

코드·PR 검토에 적용한다. 실제 변경 내용과 요구사항을 대조하며 대상 코드를 수정하지 않는다.

## 검토 대상

이슈·완료 조건, diff의 기준과 대상 커밋, 미커밋 변경 포함 여부를 확인한다. 변경 파일뿐 아니라 호출부·관련 테스트·설정 등 영향 판단에 필요한 근거를 읽는다. PR과 로컬 상태가 다르면 어느 쪽을 검토했는지 밝힌다.

## 검토 분야

| 분야 | 확인할 내용 |
|---|---|
| 정확성·회귀 | 입력·출력·상태 전이·경계 조건, 기존 계약과 호환성 |
| 테스트 | 요구 동작을 검증하는지, 중요한 실패 조건과 누락, 구현에 과도하게 결합됐는지 |
| 오류 처리 | 오류가 숨겨지는지, 복구·재시도 조건, 잘못된 성공 응답과 로그 |
| 데이터·권한 | 검증·권한 경계, 비밀정보, 데이터 손실·중복·경쟁 조건 |
| 설계·타입 | 책임과 의존성, 타입이 보장하는 조건, 변경 범위에 비해 불필요한 복잡성 |
| 문서·주석 | 실제 동작과 일치하는지, 사용법·설정·API 변경이 반영됐는지 |

변경에 관련된 분야만 깊게 검토한다. 모든 항목에 발견 사항을 만들거나 취향을 결함으로 취급하지 않는다. 프로젝트 검증 명령도 실행하기 전에 영향을 확인하고 허용된 로컬 범위에서만 수행한다.

## 발견 사항과 재검토

각 발견 사항은 위치, 발생 조건, 실제 영향, 근거 또는 재현 결과, 필요한 수정 방향을 포함한다. 심각도는 가능한 영향으로 판단한다. 확인되지 않은 우려는 질문·미확인으로 표시하고 실제 결함과 분리한다.

테스트·로그가 부족하면 검증 범위의 한계로 보고한다. 발견 사항이 없다는 것과 모든 동작을 검증했다는 것은 다르다. 리뷰 댓글 게시나 PR 승인은 검토와 별개이며 명시된 요청·권한이 있을 때만 수행한다.

작성자가 수정하면 변경된 내용과 영향 범위를 다시 확인한다. 이전 리뷰 결과를 새 커밋에 자동 승계하지 않는다. 최종 보고에는 검토한 버전·범위, 필수 수정, 추가 개선, 미검증을 구분한다.
