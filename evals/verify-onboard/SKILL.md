# 코드·분야 온보딩

처음 접하는 코드나 분야의 목적, 핵심 개념과 관계를 이해하고 다음 행동을 선택하도록 돕는다. 프로젝트 초기 셋업과 학습 기록 갱신도 지원한다.

프로젝트 온보딩은 신규·기존 트랙으로 나누며 기본 완료 범위는 개발 환경 준비와 실제 로컬 실행 확인까지다. 설명만·계획만·학습만 요청한 경우 해당 범위를 우선하고 설치나 실행으로 확대하지 않는다. 스킬 원본 생성·수정 요청은 대상 프로젝트 온보딩이나 호스트에 스킬을 설치하라는 요청으로 해석하지 않는다.

## 분야 선택

사용자가 준 대상·목적·자료·이해 수준을 활용한다. 수준이 없으면 입문자 기준으로 시작한다. 설명 방향을 결정할 수 없을 때만 짧게 질문한다. 아래에서 해당하는 참조만 읽는다.

| 대상 | 참조 |
|---|---|
| 특정 저장소의 구조·실행 방법, 로컬 셋업, 프로젝트 지식 갱신 | [코드·프로젝트](references/code.md) |
| 언어·자료형·함수·알고리즘 등 프로그래밍 개념 | [프로그래밍](references/programming.md) |
| 데이터 요약·확률·추정·가설 검정·통계 모형 | [통계](references/statistics.md) |
| 선택·자원 배분·시장·경제 지표·정책 | [경제학](references/economics.md) |

여러 분야가 필요하면 주된 분야를 먼저 설명하고 다른 분야의 필요한 부분만 연결한다. 분야별 용어와 전제를 혼동하거나 각 절차 전체를 반복하지 않는다. 목록에 없는 분야는 아래 공통 지침으로 설명하며 전문 참조가 있는 것처럼 주장하지 않는다. 분야 파일의 추가는 스킬 확장 요청이 있을 때만 한다.

## 공통 설명 방식

- 비유·은유·의인화를 사용하지 않는다. 대상의 실제 기능, 조건, 관계로 설명한다.
- 처음에 무엇이며 왜 필요한지 설명한다. 전문 용어와 약어는 첫 등장에 필요한 뜻을 풀어 쓰며, 다른 미정의 용어로만 설명하지 않는다.
- 앞의 설명으로 다음 내용을 이해할 수 있게 순서를 정한다. 선행 지식은 현재 주제에 필요한 만큼만 보충한다.
- 코드에서는 입력·처리·결과, 분야 학습에서는 정의·적용 조건·개념 간 관계를 설명한다. 공식과 기호는 뜻을 밝히고, 필요하면 같은 분야의 작은 실제 사례를 쓴다. 예시 수치·가정은 관측값과 구분한다.
- 한 문단은 한 주제에 집중한다. 반복, 불필요한 역사·예외·세부 구현은 생략하되 정확성에 필요한 조건은 남긴다. 비교가 필요할 때만 표나 목록을 사용한다.
- 단일 개념에는 해당 개념을, 분야 전체에는 핵심 개념과 관계·학습 시작점을 설명한다. 전체 교육과정과 연습 문제는 요청받았거나 학습 진행에 필요할 때 제공한다.
- 제공된 교재·문서·강의의 범위를 우선한다. 접근하지 못한 자료의 내용을 확인했다고 하지 않는다. 일반 지식·자료의 주장·추론·미확인을 구분한다. 최신 정보나 정확한 인용이 필요하면 공식 문서·원문을 확인하고 해당 주장 가까이에 링크한다.

## 실행과 기록

설명만 요청하면 답변으로 완료하며 파일 생성·설치·서비스 실행을 하지 않는다. 프로젝트 셋업·지식 기록·갱신을 요청하면 코드 참조의 검증·보존 절차를 따른다. 분야 학습에는 저장소·Git·프로젝트 설정·해시 목록·실행 보고서를 요구하거나 자동 생성하지 않는다.

노트 저장 요청은 지정한 위치와 기존 기록을 따른다. 대상·핵심 개념과 관계·근거·미해결 질문을 간결하게 남긴다. 갱신은 바뀐 근거와 설명만 반영하며 사용자 메모·확정 결정은 보존한다. 학습 기록을 모델 훈련이나 호스트의 자동 메모리로 설명하지 않는다.

## 완료 확인

비유, 정의하지 않은 용어, 반복, 무관한 세부 내용을 제거한다. 사용자의 이해·숙달을 확인 없이 단정하지 않는다. 필요한 다음 행동만 제시하고 실제 실행·저장이 있을 때만 결과와 위치를 보고한다.
