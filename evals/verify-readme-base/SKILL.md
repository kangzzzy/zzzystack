# README 작성·관리

저장소에 처음 방문한 사람이 프로젝트의 목적과 현재 상태를 이해하고 설치·실행·사용을 시작할 수 있는 README를 작성한다. 사용자가 지정한 대상 파일·독자·언어와 기존 프로젝트 형식을 우선한다.

## 자료 확인

대상 README와 프로젝트 지침, 패키지·의존성 설정, 실행 스크립트, 환경변수 예시, 주요 진입점, 기존 docs를 필요한 만큼 확인한다. 저장소 설명과 실제 구현이 다르면 현재 동작을 근거로 정리하고 계획은 계획으로 표시한다. 기존 사용자 작성 내용과 다른 작업의 변경을 보존한다.

설치 방법이나 실행 명령은 실제 설정에서 찾는다. 프로젝트 이름·저장소 URL·라이선스·지원 환경·배포 주소·완료 상태를 추측하지 않는다. 부족한 정보가 문서의 핵심을 바꿀 때만 질문하고, 나머지는 작성한 뒤 미확인 사항을 보고한다.

## 구성과 작성

프로젝트에 필요한 항목만 고른다. 작은 프로젝트에 모든 절을 강제하거나 사용자가 요청한 한 절의 수정 때문에 문서 전체를 재구성하지 않는다.

- 소개: 해결하는 문제, 대상 사용자, 현재 제공하는 핵심 기능과 개발 상태.
- 빠른 시작: 필요한 도구·버전, 실행 위치, 설치·환경 설정·실행 명령과 확인할 결과.
- 사용법: 실제 지원하는 대표 흐름이나 최소 예시. 필수 입력과 선택 설정을 구분한다.
- 개발 안내: 필요한 경우 폴더 구조, 개발·테스트 명령, 기여 방법을 설명한다.
- 문서 연결: 상세 로드맵·설계·API·운영 문서의 기존 원본으로 연결한다.

명령은 셸과 작업 디렉터리가 분명하고 복사해 사용할 수 있게 쓴다. 비밀값은 예시 값으로 표시하며 실제 토큰·개인 로컬 경로를 넣지 않는다. 배지·스크린샷·라이선스 표시는 실제 대상과 근거가 있을 때만 추가한다. 미구현 기능을 현재 사용 가능한 기능으로 소개하지 않는다.

상세 개발 산출물은 [docs](../verify-docs/SKILL.md)로 연결하고 README에는 시작에 필요한 요약만 둔다. README의 완료 체크리스트·날짜별 이력만 요청받으면 [progress](../verify-progress/SKILL.md)를 적용한다. 일반 README 작성만으로 진행 체크리스트를 새로 만들지 않는다.

## 확인과 완료

상대 링크의 대상과 제목 앵커, 예시 파일 경로, 명령과 실제 스크립트의 일치를 확인한다. 실행이 필요하고 허용된 안전한 명령만 검증하며, 배포·마이그레이션·외부 쓰기를 문서 검증 목적으로 실행하지 않는다. 실행하지 않은 명령은 실행 검증 완료로 보고하지 않는다.

diff로 요청 범위, 기존 내용 보존, 현재 기능과 계획의 구분, 비밀값 노출 여부를 확인한다. 변경 파일과 핵심 내용, 실제 확인한 사항과 남은 미확인 사항을 짧게 보고한다. 문서 작성 요청만으로 커밋·push·PR·게시를 시작하지 않는다.
