# 출시 연결

1. 어떤 커밋을 어느 환경에 반영할지 확인한다. 프로젝트의 버전 관리 도구·태그·릴리스 규칙을 따르고 임의의 버전 체계를 도입하지 않는다.
2. 해당 버전의 변경 사항·알려진 제한·설정 또는 데이터 변경·복구 방법을 정리한다. 태그·릴리스·패키지 게시도 외부 변경이므로 요청 범위와 기존 권한을 따른다.
3. 실제 환경 반영은 [release](../../release/SKILL.md)를 따른다. 기존 배포 경로가 없으면 필요한 결정을 정리하고, 별도 요청 없이 클라우드 계정·서비스·CI를 새로 만들지 않는다.
4. PR 병합, 태그 생성, 패키지 게시, 서버 반영 중 무엇이 완료됐는지 구분한다. 정상 응답뿐 아니라 이번 버전이 반영됐는지 확인한다. DB 변경 등 되돌릴 수 없는 요소가 있으면 코드 롤백만으로 복구된다고 하지 않는다.
5. 실패·철회·복구가 발생하면 실제 결과를 기록한다. 개인 프로젝트에서 README 진행 기록을 사용하는 경우 [progress](../../progress/SKILL.md)로 확인된 상태만 갱신한다.
