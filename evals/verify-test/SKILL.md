# 테스트

입력: 요구사항·수용 기준, 대상 버전·환경, 기존 테스트와 실행 방법. [공통 원칙](../../shared/core.md)을 따른다. 테스트 우선 개발은 [TDD](../verify-tdd/SKILL.md), 독립 판단은 [review](../verify-review/SKILL.md)로 연결한다. 작성자의 자체 테스트를 독립 검토로 표시하지 않는다.

1. 요구 ID와 변경 위험에 따라 단위·통합·시스템·수용·회귀 중 필요한 범위를 선택한다. 정상·경계·실패·권한 경로와 실행 조건을 정한다.
2. [테스트 양식](assets/test-report.xlsx)의 `테스트 항목`에 테스트 ID·요구사항 ID·사전 조건·데이터·절차·기대 결과를 작성한다. 요구사항 문서의 정확한 위치를 링크한다.
3. 기존 테스트를 우선 사용하고 필요한 사례를 보완한다. 격리된 환경·데이터를 사용하고 외부 전송·운영 데이터 변경은 기존 권한 범위를 따른다.
4. 실제로 실행한 명령·대상 버전·환경·증거와 실제 결과를 `테스트 결과서`에 기록한다. 테스트 ID와 실행 ID를 분리하고 재실행은 새 행에 추가한다. 판정은 통과·실패·차단·미실행으로 구분한다.
5. 결함은 `버그 리포트`에 재현 절차·기대/실제 결과·심각도·상태·담당자·발견 실행 ID를 기록하고 결과서의 버그 ID와 연결한다. 제품·테스트·환경 문제를 구분하며 버그가 없으면 버그 목록은 비워 둔다.
6. 테스트만 요청하면 제품 코드를 수정하지 않는다. 수정까지 요청하면 [구현](../verify-implementation/SKILL.md)으로 연결하고 수정 버전·재검증 실행 ID를 기록한다. 실패했던 항목과 영향받는 회귀를 재검증하며 이전 실패를 덮어쓰지 않는다.

산출물: 테스트 항목에 대응하는 테스트 결과서와 버그 리포트를 포함한 `.xlsx`, 실행 증거. 표 간 ID 연결·중복 검사를 확인하며 예약 범위를 넘으면 수식과 검증도 확장한다.

완료: 요청한 테스트의 결과 또는 실행 불가 이유가 대상 버전에 연결되어 있다. 테스트 작업 완료와 제품 기준 통과를 구분하며 미실행을 통과로 표시하지 않는다. [배포](../verify-release/SKILL.md) 전 필수 검증 실패·차단을 드러낸다.
