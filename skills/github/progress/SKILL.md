# README 진행 기록

개인 프로젝트의 README에 완료 조건별 체크리스트와 실제 진행 이력을 간결하게 남긴다. 사용자가 개인 프로젝트라고 지정했거나 이 기록 방식을 요청·채택한 프로젝트에 적용한다. 비공개 저장소라는 이유만으로 개인 프로젝트라고 판단하지 않는다.

## 범위와 근거

대상 README, 기존 진행 섹션·이슈·PR·테스트·릴리스 기록을 확인한다. 사용자가 지정한 파일과 언어·기존 형식을 따른다. 현재 자료로 알 수 없는 상태를 Git 커밋 메시지나 작성자의 주장만으로 완료 처리하지 않는다.

이슈나 Feature Map 등 기존 완료 기준이 있으면 이를 요약하고 연결한다. README에 경쟁하는 별도 작업 목록이나 완료 기준을 만들지 않는다. 없는 완료 기준은 요청에서 관찰 가능한 조건으로 정리하고, 범위가 달라지는 선택은 확정 사실로 기록하지 않는다.

## 체크리스트

- 항목은 기능이나 이정표의 확인 가능한 완료 조건으로 작성한다. 새 항목은 미완료로 시작하고 실제 근거가 충족한 항목만 체크한다.
- 구현·검증·병합·출시의 의미가 다르면 별도 항목 또는 명시적 상태로 구분한다. PR 생성은 병합 완료가 아니며, 병합은 배포 완료가 아니다.
- 검증을 실행하지 못한 항목은 미완료 또는 미검증으로 남긴다. GitHub에서 이슈가 닫혔더라도 그 사실만으로 출시를 체크하지 않는다.
- 진행률은 분모와 기준이 명확할 때만 사용한다. 체크 수를 제품 품질이나 출시 준비율로 해석하지 않는다. 취소·범위 제외는 완료 체크로 바꾸지 않는다.

## 타임라인

의미 있는 상태 변화만 날짜·단계·내용·근거로 기록한다. 모든 커밋이나 실행 로그를 복사하지 않는다. 요청·프로젝트에 지정된 시간대를 사용하고 날짜 경계가 중요한 경우 시간대도 표시한다.

실제 사건 날짜는 PR 병합·배포·검증 기록 등 근거에서 확인한다. 지금 노트를 갱신했다는 이유로 과거 완료 날짜를 오늘로 쓰지 않는다. 날짜를 알 수 없으면 `날짜 미확인`으로 남기거나 날짜 확인이 필요한 항목으로 분리한다. 예정일은 실제 이력과 분리하고 `예정`으로 표시한다.

같은 사건을 다시 기록하지 않도록 이슈·PR·커밋·릴리스 식별자로 기존 항목과 대조한다. 단순 재실행은 새 이력이 아니다. 재개방·회귀·배포 철회는 이전 이력을 지우지 않고 새 사건으로 남기며, 현재 완료 상태가 달라졌다면 관련 체크도 갱신한다.

## 편집과 확인

기존 진행 섹션만 필요한 만큼 수정한다. 없으면 [기본 서식](assets/readme-progress.md)을 참고해 체크리스트와 타임라인을 추가한다. 서식의 자리표시는 실제 내용으로 바꾸고 확인되지 않은 예시를 완료 이력으로 넣지 않는다. 요청이 체크리스트 또는 타임라인 한쪽뿐이면 해당 부분만 만든다.

사용법·설치 안내·배지·사용자 메모·기존 이력은 보존한다. 공개 README에는 비밀값·개인정보·로컬 절대 경로를 넣지 않으며 내부 자료는 공개 범위에 맞게 요약한다. 깨진 상대 링크와 확인할 수 없는 근거를 점검한다.

수정 후 diff에서 변경 범위, 체크 상태와 근거, 날짜, 중복·모순을 확인한다. 완료 보고에는 바뀐 항목과 미확인 사항만 전달한다. README 갱신 요청만으로 이슈 생성·종료, 커밋·push·PR·배포를 실행하지 않는다.
