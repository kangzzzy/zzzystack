# Git 작업

## 로컬 작업 준비

저장소 루트, 현재 브랜치, remote·upstream, 작업 디렉터리의 변경을 확인한다. 프로젝트의 기준 브랜치와 브랜치명 규칙을 따르며 `main`·`master`·`origin`을 고정값으로 가정하지 않는다. 이슈 번호는 기존 규칙에 맞춰 브랜치나 커밋에 연결한다.

작업용 브랜치를 만들거나 기존 작업 브랜치를 재사용한다. worktree는 별도 작업 공간이 필요한 경우에만 사용한다. 사용자 변경을 임의로 stash·삭제·커밋하거나 다른 브랜치로 옮기지 않는다. 기존 변경 때문에 작업이 불가능하면 충돌 지점과 선택지를 먼저 설명한다.

## 변경과 커밋

요청한 구현과 관련 문서를 수정하고 의미 있는 검증을 수행한다. TDD를 요청했거나 프로젝트 규칙에 있으면 TDD 절차를 적용한다. 커밋 전 diff와 staged diff를 확인하고 작업 관련 파일·부분만 선택한다. `git add -A`로 모든 변경을 무조건 포함하지 않는다.

비밀값, 자격증명, 로컬 설정, 불필요한 생성물은 커밋하지 않는다. 추적 중인 비밀정보를 발견하면 내용을 출력하지 말고 영향과 대응 필요성을 보고한다. 파일 삭제만으로 과거 이력에서 제거됐다고 하지 않는다.

커밋은 변경 목적을 설명하며 프로젝트 규칙을 따른다. 기존 사용자의 커밋을 승인 없이 amend하거나 작성자를 바꾸지 않는다. 검증 실패를 숨기기 위해 훅이나 검사를 끄지 않는다.

## 동기화·충돌·복구

원격 차이는 fetch 후 확인하고 프로젝트 정책에 맞춰 merge 또는 rebase를 선택한다. 인증 실패를 코드 동기화 문제로 판단해 임의 pull하지 않는다. 공유 이력의 재작성은 기존 권한과 영향을 확인한다.

충돌은 양쪽 변경 의도와 관련 테스트를 읽고 해결한다. 한쪽 파일 전체를 자동 채택하지 않는다. 해결 후 diff와 영향받는 테스트를 다시 확인한다. 판단이 필요한 제품 요구 충돌은 사용자에게 남긴다.

push 대상 저장소·브랜치·upstream을 확인하고 성공 여부를 원격 상태와 대조한다. 강제 push가 승인된 경우에도 원격 변경을 확인하고 가능한 경우 `--force-with-lease`를 사용한다. 이 옵션이 동시 작업 손실을 모두 방지한다고 가정하지 않는다.

되돌리기는 로컬 미공유 변경과 공유된 커밋을 구분한다. 공유 이력은 프로젝트 정책에 맞는 revert를 우선 검토한다. reset·clean·브랜치 삭제처럼 변경을 잃을 수 있는 작업은 대상과 복구 가능성을 확인하며, 승인 범위를 넘어 실행하지 않는다.
