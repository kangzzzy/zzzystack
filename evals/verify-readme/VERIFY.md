# README 실험

[공통 평가 규칙](../VERIFY.md)을 먼저 적용한다. 현재 후보는 [임시 README 스킬](SKILL.md)이다. 정식 README나 설치된 스킬을 교체하는 작업은 포함하지 않는다.

## 입력과 실행

대상은 zzzystack 저장소다. 루트 README, package.json, VERSION, skill-registry.json, docs/roadmap.md, docs/implementation-status.md와 필요한 소스를 입력으로 확인한다. 비교 실행에서는 해당 파일의 같은 버전을 사용한다.

사용자 요구: “프로젝트 목표랑 현재 진행 상태를 먼저 보여주고, 설치·사용법은 간결하게, 상세 내용은 docs로 연결하고 싶어.”

새 실행 요청 예시:

```text
evals/VERIFY.md와 evals/verify-readme/VERIFY.md를 읽고,
evals/verify-readme/SKILL.md를 적용해 zzzystack의 README 후보를 작성해줘.
기존 비교 결과는 읽지 말고 results/ 안에 새로운 이름으로 저장해줘.
정식 README와 스킬은 수정하지 말고 실행 조건과 검사 결과를 기록해줘.
```

평가는 저장소 루트를 작업 디렉터리로 사용한다. `results/`에 저장하는 README의 상대 링크는 파일 위치에 맞춰 작성한다. 정식 README로 채택할 때는 루트 위치 기준으로 다시 조정한다.

## README 전용 기준

| 항목 | 통과 조건 |
|---|---|
| 첫 부분 | 제목 다음에 프로젝트 목표와 현재 상태가 나타나고 설치보다 앞선다. |
| 상태 | 장기 목표와 현재 구현을 구분하며 버전·스킬 수·검증 상태가 입력과 일치한다. |
| 설치 | 준비 사항·실행 위치·대표 설치 명령이 있어 따라 할 수 있고 선택 사항은 짧게 설명한다. |
| 사용법 | 대표 요청 두세 개로 호출 방법을 보여준다. |
| 상세 내용 | 실제 docs 문서로 연결하고 전체 스킬 목록·긴 이력·폴더 구조를 중복 나열하지 않는다. |

링크·명령·상태 확인은 기술 검사로 기록한다. 분량이 적절한지와 목표·상태를 빨리 파악할 수 있는지는 사용자 관점의 품질 판단으로 기록한다. 설치 명령의 존재를 확인한 것과 실제 설치 성공은 구분한다.

## 현재 결과와 결정

- [세 번째 비교본](results/readme-test3.md): 목표·상태 우선 구성의 탐색용 초안. [실행 기록](results/run-notes.md)에 확인 범위와 한계를 남겼다.
- 첫 번째·두 번째 비교본은 정리 시점의 작업 폴더에서 찾을 수 없었다. 재생성하거나 복원하지 않았다.
- 정식 채택: 미결정. 현재 실험 결과만으로 정식 스킬을 교체하지 않는다.
