# 이슈 관리

- 대상 저장소와 기존 이슈를 확인한다. 제공된 이슈가 있으면 본문·댓글·연결 PR을 읽고 기존 결정을 재사용한다.
- 신규 이슈에는 문제·목적, 포함/제외 범위, 관찰 가능한 완료 조건, 검증 방법, 관련 자료와 의존성을 담는다. 기존 이슈 서식과 라벨 규칙을 따르고 불명확한 요구를 확정 사실로 쓰지 않는다.
- 작업이 서로 다른 완료 조건을 가지거나 독립 출시가 필요하면 분할한다. 작은 작업에 불필요한 하위 이슈를 만들지 않는다.
- 이슈 생성·수정이 요청 범위에 포함되면 실제 결과에서 번호와 URL을 확인한다. 연결이나 권한이 없으면 초안으로 보고하며 등록됐다고 하지 않는다.
- 로컬 작업과 PR에 이슈를 연결한다. `Closes #번호` 같은 자동 종료 문구는 해당 PR의 병합으로 완료 조건을 충족할 때만 쓴다. 배포 확인이 완료 조건이면 병합만으로 이슈를 종료하지 않는다.
- 이슈가 자동 종료됐어도 실제 완료 조건과 다르면 불일치를 보고하고 허용된 범위에서 상태를 정정한다. 이슈 종료와 운영 출시를 별도로 기록한다.
