# 스킬을 별도 작업자에게 위임하기

현재 호스트에 따라 [Claude Code](../../../hosts/claude-code.md) 또는 [Codex](../../../hosts/codex.md)를 읽는다. 전문성은 [각 스킬의 전문 지침](roles.md)에 있으며 고정 agent 등록을 요구하지 않는다.

## 실행을 분리하는 조건

일반 기획·설계·구현은 현재 세션에서 해당 스킬과 필요한 전문 지침을 적용한다. 별도 맥락이 필요한 탐색, 범위가 분리된 구현, 독립 판단·검토에만 호스트의 범용 agent 또는 별도 세션을 사용한다. 독립 검토는 작성자와 다른 실행이어야 한다. 역할이 여러 개라는 이유만으로 agent를 각각 생성하지 않는다.

## 실제 위임

1. 현재 작업 스킬과 프로젝트의 확정된 역할 배정에서 필요한 전문 지침을 선택한다. 관련 없는 지침은 읽히지 않는다.
2. 호스트에서 실제 사용 가능한 범용 agent/별도 세션, 권한과 작업 범위를 확인한다. 고정 이름 `backend`나 `reviewer`가 설치돼 있다고 가정하지 않는다.
3. [위임 패킷](../assets/delegation.md)에 작업 스킬·전문 지침·[공통 원칙](core.md)·[위임 계약](delegation.md)의 실제 경로와 작업 범위·기준·산출물·한도를 전달한다. 작업자는 실행 전에 이 문서들을 읽는다. 파일 접근이 불가능한 별도 세션에는 필요한 내용을 패킷에 포함한다.
4. 검토자는 대상 결과물을 수정하지 않는다. 호스트가 작업별 read-only 권한을 지원하면 적용한다. 지원하지 않으면 비수정 지침과 허용 검증 범위를 명시하고 권한이 강제된다고 주장하지 않는다. 비파괴 검증에 필요한 임시 출력은 허용 범위 안에서만 만든다.
5. 위임 자체가 불가능하면 기획·작성은 현재 세션에서 수행할 수 있다. 독립 검토는 패킷을 저장하고 `review_pending`으로 남긴다. 이미 검토자로 위임받은 실행은 직접 검토하며 다른 검토자를 다시 생성하지 않는다.
6. 부모가 결과와 근거를 원래 완료 조건에 대조하고 다음 스킬 또는 사용자 판단으로 연결한다. 모델을 임의로 강제하거나 승인 범위 밖 병렬 실행을 시작하지 않는다.

## 작업별 지침 선택

| 작업 스킬 | 필요한 경우 적용하는 전문 지침 |
|---|---|
| [plan](../../plan/SKILL.md) | 웹 기획; UX·아키텍처 쟁점 협의 |
| [design](../../design/SKILL.md) | 웹 아키텍처·UX/UI·DB 설계 |
| [build](../../build/SKILL.md) | 프런트엔드·백엔드·DB |
| [review](../../github/review/SKILL.md) | 검토자 기준; QA·보안 |
| [release](../../github/release/SKILL.md) | 배포·서비스 운영 |
| [investigate](../../investigate/SKILL.md) | 문제 영역의 전문 지침; 부모가 결과 취합 |
| [handoff](../../handoff/SKILL.md) | 부모가 기록 종합; 새 실행은 필요한 경우만 |

웹 이외 분야는 책임·입력·산출물·검증 기준을 먼저 정한다. 프로젝트당 순차 정책과 전체 자원 한도는 호스트가 지원하는 동시 실행 수보다 우선한다.
