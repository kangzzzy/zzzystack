# 목표와 진행 상태 중심 README

프로젝트를 처음 보거나 다시 시작하는 사람이 목표, 현재 위치, 시작 방법을 빠르게 파악할 수 있도록 작성한다. 사용자 지정 출력 파일과 언어를 따른다. 비교 실험에서는 기존 README와 다른 실험 결과를 유지하고 지정된 새 파일에 쓴다.

## 근거 확인

기존 README, 프로젝트 지침, 패키지·실행 설정, 로드맵, 상태 기록과 관련 소스를 확인한다. 전체 구조를 파악하되 모든 파일을 무조건 읽지는 않는다. 현재 상태는 최신 관리 원본으로 확인하고, 과거 구현 기록의 수치나 테스트 통과를 현재 버전의 검증 결과로 옮기지 않는다.

## 작성 순서

1. **제목과 목표:** 프로젝트가 무엇을 달성하려는지 첫 부분에 쓴다. 장기 목표와 지금 제공하는 기능을 구분한다. 배지·목차·설치 명령이 목표와 상태보다 앞서지 않게 한다.
2. **현재 진행 상태:** 개발 단계, 구현된 범위, 미완료·미검증 범위를 짧은 문장이나 표로 보여준다. 작업 목록·판정 기준이 있으면 요약하고 원본에 연결한다. 분모 없는 진행률이나 근거 없는 완료 체크를 만들지 않는다.
3. **간결한 설치:** 필수 준비 사항, 실행 위치와 대표 설치 경로 하나를 제공한다. 선택 가능한 호스트·범위는 필요한 만큼만 설명한다. 문서를 줄이려고 실제 실행에 필요한 전제 조건을 빼지 않는다.
4. **간결한 사용법:** 대표 요청 두세 개로 사용 방법을 보여준다. 전체 기능·스킬 목록과 관리 명령은 나열하지 않는다.
5. **상세 문서:** 기존 `docs/`의 로드맵·설계·개발·검증 문서로 설명이 있는 링크를 제공한다. README에서 상세 내용을 복제하지 않는다.

사용자가 달리 요청하지 않으면 긴 목차, 전체 폴더 트리, 전체 스킬 목록, 변경 이력은 생략한다. GFM 표와 코드 블록은 정보 비교와 실행 안내에 필요한 만큼 사용한다. 실제 로고가 있고 내용 탐색에 도움이 되면 제목 곁에 배치하되 장식용 이미지를 새로 만들지는 않는다.

별도 파일로 관리하는 기여 안내·라이선스·변경 이력을 README 안에 다시 작성하지 않는다. 필요한 상세 문서가 없으면 존재하지 않는 경로를 링크하지 않고 필수 안내를 README에 남긴다. README 작성만 요청받은 경우 새 docs 문서나 디렉터리를 임의로 만들지 않는다.

## 결과 확인

- 첫 부분만 읽어도 목표와 현재 진행 상태가 구분되는가?
- 설치·사용 예시에 실행 위치·필수 조건·대표 동작이 있는가?
- 상세 내용은 실제 존재하는 docs 원본으로 연결되는가?
- 현재 상태·수치·명령이 관리 원본과 일치하며 미검증 상태를 숨기지 않는가?
- 지정한 출력 파일만 바뀌었는가? 실행하지 않은 검증을 통과했다고 보고하지 않았는가?

파일 링크·제목 앵커와 명령 정의를 확인하고 수정한다. 문서를 검증하려고 설치·배포 등 외부 변경을 실행하지 않는다. 결과 파일과 확인 범위를 간단히 보고한다.
